# 没有图层坐标时怎么定位：通用 02 问题点

对象：`工作流/02-H3漫剧流程/H3-通用02-高清主线-参考音色对白-r2v-25step-1344x768.json`
（`MiniMaxH3Director`，r2v / 25 步 / 1344×768 / 参考音色对白）。

NG 06 靠 `x / y / scale` 摆人；这条线没有故事板节点，靠**图 + 提示词**摆人。本文把「换了工作流以后
站位怎么办」的疑问逐条收在这里，便于对照排查。坐标换算与 06 的操作流程见
[导出到 NG 故事板](ng-storyboard-export.md)、[运行手册](ng-storyboard-runbook.md)。

**证据标记**（每条答案都带，别混用）：

- 【实测定】本机解析工作流或实跑命令得到的
- 【README】该工作流目录 `README.md` 或节点内置说明的原话
- 【推断】据上述事实推的写法，**没有真跑过**，用前先按 Q12 的花费验证

## Q1 · 转换器能直接把面板注入这个模板吗

**现在能——但产出的是 segments 草稿，不是 06 那种成品注入。**【实测定】

转换器已加 02 线适配分支：模板没有 `NGStoryboard` 但有 `MiniMaxH3Director` 时，panels 自动
写成 segments（段长对齐 17 网格、夹进 102~204 产能区间；refs=人物+场景板；negativePrompt
英文；分镜「音色」非 none 的段补 `Audio: reference`）。注入后节点/连线拓扑不变。

```
$ python scripts/storyboard_to_ng.py 分镜.md --out t.json \
    --workflow "…/H3-通用02-高清主线-…json" --out-workflow t.wf.json
MiniMaxH3Director 已写入 N 个 segment、总时长 …s（taskType=r2v、refs=人物+场景、negativePrompt 已填英文）
```

四件事仍是手工的（注入报告会逐条提醒）：**挂参考音色 wav**、refs 换成身份板/场景板（现在
指向抠图或占位图）、按 voice-layer-craft.md 补 subject_definitions 与声音层空间词、竖屏要改
output 的 aspectRatio 与宽高（模板固定 16:9）。

两套结构差异照旧（它是**另一条技术路线**，prompt 驱动单段生成，没有拼贴图层）：

| | 通用 02 | NG 06 |
|---|---|---|
| Director | `MiniMaxH3Director` | `NGH3Director` |
| 故事板 | **无** | `NGStoryboard` + 3 张 `NGContextImage` |
| 执行单位 | `segments[]`（每段自带 prompt / refs / refAudios） | `shots[]` + panel 图层 |
| 构图控制 | 提示词 + `<Picture 1>` | `x / y / scale` 坐标 |

**判定方法**：打开模板 JSON，`nodes[].type` 里没有 `NGStoryboard` 就按 02 路径注入。

## Q2 · 文件名里的「通用」是什么意思

指模板可跨项目复用（01 试错 → 02 出片 → 03 精修，按使用顺序编号），不是「接口通用、谁都能对接」。
【README】两套工作流的「通用」不互通：06 通用的是**摆位方式**（坐标），02 通用的是**镜头类型**
（单段 r2v + 对白），后者不承载故事板那层数据。

## Q3 · 没有坐标，那靠什么定位

三层杠杆，优先级从高到低：【README】+【推断】

1. **`<Picture 1>` 这张图**——模板说明原话：「起始构图（谁左谁右、面对面还是肩并肩）由
   `<Picture 1>` 决定，**prompt 压不过它**」。图里怎么排，出来就怎么排。
2. **提示词的空间句法**——顺序、朝向、纵深、裁切位置（写法见 Q5）。
3. **排除式约束**——「不肩并肩」「中间没有任何人」「不居中对称」，堵常见失败模式。

所以「用提示词准确定位」这个问法本身要拆开：**位置交给图，提示词管朝向、动作、镜头**。指望靠
文字把 0.30 / 0.70 精确钉住，在 r2v 里做不到；那是 06 的活。

## Q4 · 提示词能控住哪些、控不住哪些

| 维度 | 力度 | 说明 |
|---|---|---|
| 谁朝谁、是否面对面 | **强** | 【README】明确要求写「侧对镜头、面对面、一左一右，绝不肩并肩」 |
| 景别、机位高度、镜头运动 | **强** | 与 06 面板里的景别同一套词表 |
| 谁在左 / 谁在右 | 弱 | 有倾向但不保证，图会盖过去 |
| 谁在前 / 谁在后 | 中 | 「靠后一步」有效，「相距 1.2 米」无效 |
| 遮挡关系（谁挡谁） | 中 | 依赖图里的深度，词只能提示 |
| 精确占比、精确间距 | 弱 | 别写百分比，写「到腰以上」「占画面一半」 |
| 三人以上的相对位置 | 控不住 | 见 Q7 |

## Q5 · 那段【】模板该怎么填

填法按五个要素固定顺序写，全部写成**可判定的句子**，不写形容词：
`机位与构图 → 位置 → 朝向与关系 → 光线质感 → 排除`。

原模板是占位：

```
【镜头内容：谁在画面左侧、谁在右侧，身体朝向谁；做什么动作；兵器是否握在手里。
 双人戏必须写明「两人身体侧对镜头、面对面，一左一右互相对视，绝不肩并肩」。】
```

以《验证-端到端样例/EP001》的双人中景（陈屿左 0.30 / 林知夏右 0.70）为例，填成：【推断】

```
<Picture 1> 是陈屿与林知夏的关系参考：两人身高差、站位与服装以它为准；
<Picture 2> 是雨夜门廊的空间与光线参考（没挂场景板就删掉这半句）。

【机位与构图】中景双人，机位与两人胸口同高，固定镜头，两人都取到腰以上，
画面上缘留出门檐。

【位置】陈屿在画面左侧三分之一，身体占画面高度约一半；林知夏在右侧三分之一，
比他靠后约半步，肩线略低于他。两人之间留出约一个身位的空隙，中间没有任何人。

【朝向与关系】两人身体侧对镜头、面对面，一左一右互相对视，绝不肩并肩；
陈屿微微前倾，视线落在林知夏眼睛上；林知夏下巴略抬，回看他。

【光线】雨夜，门廊顶灯自上而下照明，两人面部与衣料纹理清晰受光，禁止逆光剪影。

【排除】不并排站立、不居中对称、不多余人物、无字幕文字水印、无分屏。
Audio: reference
```

五处写法上的关键：

| 不写 | 改写 |
|---|---|
| 在左边 / 在右边 | 在画面左三分之一 / 右三分之一 |
| 站在后面 | 比他靠后约半步，肩线略低 |
| 全身 | 脚踩画面下缘 / 只到腰以上 |
| 两个人 | 中间没有任何人（把第三个人堵死） |
| 面对面 | 身体侧对镜头、面对面、一左一右互相对视、绝不肩并肩 |

## Q6 · 双人镜的身份和构图怎么同时保证

只挂一张单人身份板，另一个人在画面里没有任何约束，脸和身高都会漂。【推断】

建议 `Picture 1` 用一张**双人同框图**：两人相对身高、站位、服装都正确，图和文字说的是同一件事。
这也是 06 的产出物——06 把两人摆到 0.30 / 0.70，Redraw 出一张双人静帧，这张图正好是 02 要的
`<Picture 1>`。

**未验证**：拼贴图（抠图质感）当身份板，模型会不会把两人混成一个 `<Subject>`，得按 Q12 试。
若混了，退一步用「两人合拍的设定图」而不是拼贴图。

## Q7 · 三人以上怎么办

提示词控不住三人的相对位置，这是能力边界不是写法问题。三条出路：

- 拆镜：三人同框的长镜改成「两人 + 第三人画外音」或反打
- 靠图：`Picture 1` 直接用三人关系图，提示词只写朝向与动作
- 回 06：需要精确定位就用坐标摆，再按 Q8 串过来

## Q8 · 06 和 02 怎么串

分工是「06 造图、02 出片」：【推断】

1. 06 用坐标摆位 → `Redraw all panels` → 得到构图正确的静帧
2. 该静帧当 02 的 `<Picture 1>`
3. 02 里挂参考音频，段尾 `Audio: reference`，台词逐字进 prompt，25 步出片

两条链各自的长处都留着：坐标负责「摆在哪」，25 步 + 音色参考负责「出成片」。

## Q9 · 最常见的失败模式

| 现象 | 原因 | 处置 |
|---|---|---|
| 两人肩并肩站着 | 没写「绝不肩并肩」 | 按 Q5 补朝向句 |
| 画面多出第三个人 | 只描述了两个人，没堵空位 | 加「中间没有任何人」「画面内只有这两人」 |
| 左右反了 | 提示词被 `Picture 1` 压过 | 改图，不要改词 |
| 元素被放大得刺眼（血迹、绷带） | 【README】「首帧里的元素会被忠实放大」 | 出片前审 `Picture 1` 素材 |
| 中文负面词没效果 | 【README】「中文 negative 对 H3 几乎无效」 | 重要禁项写进正向 prompt |
| 台词念错 / 音轨被切 | 台词没逐字写，或段长 < 朗读时长 | 台词逐字，段长 ≥ 朗读时长 |
| 只跑 4 步出对白 | 【README】4 步下语音语义崩坏（实测是乱码） | 对白镜必用 25 步 |

## Q10 · 竖屏短剧能用吗

默认不能直接用。【实测定】该模板 `output` 固定 `aspectRatio=16:9`、`width=1344`、`height=768`，
节点内置落点表只给 16:9（0.98MP → 1344×768）。分镜是 9:16 的场次会被按横屏构图裁掉。

要竖屏得改 `output.aspectRatio` 与 width/height（短边保持 H3 原生的 768），落点没有官方表，
改完先在 01 的四步模板里试构图，别直接上 25 步。

## Q11 · 对白镜要额外准备什么

【README】三件事：

1. 时间轴目标段的「片段参考音频（音频 1–3）」挂该角色参考音频，多角色各挂各的
2. 段尾写 `Audio: reference`（模板已默认写）
3. 台词逐字进 prompt；段长 ≥ 朗读时长（实测 7.3s 台词放进 5.17s 段，结尾被切）

音色相似度取决于参考音频质量：干净人声、10 秒以上为宜。

## Q12 · 一处写法怎么低成本验证

**别拿 25 步试写法**（单段 15–25 分钟）。用 01 快出（4 步 / 960×544 / 2–4 分钟）把构图和朝向试出来，
定了再上 02。【README】

注意 4 步只适合看构图与动作：它的语音是崩的，对白镜不能靠 01 验收音轨。

## Q13 · 场景要不要生产「全方位」场景资产（多角度场景板）

**不需要。** 这条线的分工是「一张场景板管地方，每镜一张起始帧管机位」，多角度场景资产两头不沾。

【实测定】EP001 六个工作流 28 段的真实参考图配置：

| 图 | 出现次数 | 角色 |
|---|---|---|
| `IMG-CORRIDOR-PLATE.png` | 26 次 | **全场唯一一张场景板**，同一走廊从头用到尾 |
| `IMG-*-SHEET.png`（两张身份板） | 12 / 20 次 | 人物身份 |
| `frames_v3/v4/SHOT-EP001-*.png` | 每个文件恰好 1 次 | **每镜一张独立起始帧**，机位与构图由它承载 |

每段 refs 只有 3–5 张，从未接近 9 张上限。场景一致性不是靠多角度堆出来的。

不做的三个理由：

1. **参考图是语义参考，不是几何投影。**【README】挂一张背面角度的场景板，不会让镜头转到背面；
   机位由起始帧和 prompt 决定。`retention_analysis` 里场景是 `partially_preserved`——保的是
   「走廊深度、窗户顺序、灯位」这类可数地标，不保视角。
2. **多挂场景图有实测反效果。**【SKILL.md】近景类关键帧挂地点板生成时，图片常被拉宽成中远景；
   规范甚至写明「出图仍偏宽就这一镜不挂地点板，把背景写进正文」。全方位 = 每镜挂更多场景图 =
   更多拉宽风险。
3. **槽位经济学不划算。**【SKILL.md】参考图优先级：起始帧 > 正在说话的人物 > 必须认出的道具 >
   **地点** > 其余人物 > 定调图。地点本来就排在道具后面；打斗镜 4 张起步（起始帧 + 双方身份板 +
   场景板），每加一个角度的场景板就挤掉一个人物或道具槽。

还有一个隐性代价：[交接](shot-handoff.md) 的标准做法是「同一张场景板 + 同一句光位 + 同一 seed」
重出结束帧——靠的就是**同一张**的可复用性。场景板一套多角度后，「同一张」不复存在，交接反而退化。

**什么时候确实要第二张**：一场戏跨越多个地点单元（门廊 / 街面 / 巷口各拍各的），每个单元一张，
按 Q5 的 `<Picture N>` 语义各归各位。那叫两个地点，不叫全方位；判据是「机位转过去还是同一个地方吗」——
是，就一张；不是，才加。

## Q14 · 同一个场景换角度，一致性还保得住吗

**保得住，但不是生成时"对齐"出来的，是同源派生出来的。** 先记住底线：

> 两镜都挂"场景板"但没有共用结束帧——场景板只保证「是同一种景」，不保证「是同一个地方」。【实测定，shot-handoff 反例原文】

也就是说，换角度的镜**各自挂场景板直接生成**，结果就是"同一种景"：走廊还是走廊，但窗户数量、
灯位、台阶数会漂。一致性要靠下面这条派生链，一环都不能跳。

### 一致性四级来源（从强到弱）

| 级 | 做法 | 适用 |
|---|---|---|
| L1 | **从前一镜成片末帧抽帧**（`ffmpeg -sseof -0.1`） | 角度不变或顺滑衔接的相邻镜 |
| L2 | **同一张场景板 + 同一句光位 + 同一 seed** 重出本镜起始帧 | **换角度的正解** |
| L3 | 场景定调图作最后一张参考、**只取色调光线质感、不取构图** | 全集画风统一（每场先出一张中远景并接受） |
| L4 | 各镜只挂场景板、起始帧各自文生 | 等于没做，就是把误差写进概率 |

换角度时 L1 用不上（角度变了，末帧不能直接当下一镜首帧），所以 L2 是主力。

### 关键实证：场景板本身就是「双视面板」

EP001 的场景板不是一张单角度图，提示词原文是 **two-panel**：

- **Panel A**：from the street looking up at the porch——街上仰望门廊（低机位仰拍族）
- **Panel B**：from inside the porch looking out——门廊内看街道（反打、框中框族）

同一张图、一次生成、内部自带本场实际会拍的两个机位方向，且提示词里写死了
`fixed architectural anchors`（固定建筑锚点）。SHOT-001 低机位仰拍对应 Panel A 方向，
SHOT-003 门框框中框对应 Panel B 方向——**双视覆盖了全场两个机位族**。

这就是 Q13「不做全方位」和「换角度要一致」同时成立的解法：**角度进场景板，按机位族出双视或三视面板，
不按方位出全方位**。一张图保住"同一张"的交接复用性，内部多面板覆盖实际要拍的几个方向。
判据还是那句：机位转过去还是同一个地方吗——是，进同一张面板；不是，另立地点。

### 视觉设定层要同时锁住的三样

派生链成立的前提是**每次派生读的是同一份事实**：

1. **光位事实句唯一**：视觉设定里光只写一遍（如"暖黄钨丝灯吊在门廊正中偏西；街面路灯冷白，
   反光积在湿沥青上"），所有角度的起始帧提示词逐字引用这一句，不逐镜改写。
2. **识别锚点可数**：两级台阶、雨棚沿口断线雨水、玻璃门褪色营业时间、湿沥青冷蓝反光——
   全是可数、可辨认的具体物。换角度的镜，冻结关键帧正文把**本机位看得见的锚点**点名
   （背面的镜就写"褪色营业时间贴纸不在画面"或干脆不提，不硬编）。
3. **画风句全剧同一句**：每条关键帧正文用同一句画风收尾（`realistic Chinese short-drama keyframe, no text, no logo`），
   换角度不许换画风词。

### 会破掉一致性的三种操作

- 换角度的起始帧**换了光位措辞**（"灯光从西边来" vs "正中偏西"）——模型读成两套光
- 双视面板生成时**没写 fixed architectural anchors**——两个 panel 各漂各的
- 场景板改版后只重出了部分镜的起始帧——新旧两批起始帧共存在同一场里，成片前后两个世界

## 附：这条线不值得做的四件事

- 不要把 02 注入产物当成品直接跑 25 步（Q1）——那是 segments 草稿，音色、refs、subject_definitions 三件事手工补完再出片
- 不要试图用提示词替代坐标（Q3），那是把 06 的活搬到没有工具的地方
- 不要跳过 01 直接用 25 步调写法（Q12），一次试错 20 分钟的成本全在排队上
- 不要为机位做全方位场景板（Q13），机位是起始帧的活，场景板只管「是什么地方」
