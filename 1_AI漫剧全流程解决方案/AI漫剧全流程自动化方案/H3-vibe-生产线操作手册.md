### 0.2 路线定线依据（r2v / fl2v 双路线 · 设计态 + 实跑修正）

> **先看结论（2026-11-25 实跑修正）**：下面这段"为什么只能是 r2v"是 **11-18 设计态**的推理，保留作证据链回溯；但 11-23~24 的真实出片（经验库 27.7 / 28.10~28.19）**源码级证伪了 r2v 的身份能力**——r2v 把参考图转成 `ref_image_0~3` 的 Qwen3-VL 语义条件、逐帧重画，换拼贴板/干净肖像/inswapper/FaceRefine 四条路都守不住脸；**fl2v 首帧像素锁才是身份正解**。现行定线已改为双路线，务必按下方「实跑修正」执行，不要只照读设计态推理。

**设计态定线（2026-11-18，历史证据链）**：

- `fl2va` 只提供音频 `lock`（原音直贴、台词不可改），不提供 `ref` 借音色；`09-H3导演台-NG版/_上游文档/docs/NG-shot-audio.md:46` 写死 `In FL2VA only lock is offered`。
- drama 官方 `skills/short-drama-video-prompts/references/minimax-h3.md:68-73` 的模式表：

  | 本镜绑定的图 | H3 模式 | 正文结构 |
  |---|---|---|
  | 无图，明确文生视频 | Base | 三段 |
  | 只有一张 `用途：起始帧` | `first_frame` | 三段 |
  | 起始帧 + 结束帧 | `first_last_frame` | 三段 |
  | **起始帧 + 人物／地点／道具图同时存在** | **`reference`（full-reference）** | **六段** |

  本链路正好落在第四行。`:81-84` 补充说明：「H3 的首/尾帧输入与参考输入**互斥**……整组统一走 full-reference，起始帧也以 `reference_image` 送入」。所以**不是「选了 r2v」，是「链路结构决定了只能是 r2v」**；而 `<Audio N>` 音色参考只存在于六段式里，这又反过来解释了为什么 `fl2va` 走不通。

**实跑修正 · 双路线定线（2026-11-25，以经验库为准）**：

上段"互斥"在设计态成立，但实跑证实**互斥的代价是身份失控**。H3 源码 `executor_core.py:_build_minimax_inputs()` 显示：r2v 把 `refs` 转 `ref_image_0~3` 当**语义条件**（`tensor[:1]`），模型按"霸总/校服"这类概念重画，不锚像素；fl2v 则把 `segments[i].genImage.imageFile` 当**首帧像素锚**。S003 单镜实测（124 帧 / 5.17s）：fl2v 首帧与静帧像素级一致、全程身份硬朗男性、眨眼张口自然（经验库 28.11/28.17/28.18）。因此定线改为：

| 路线 | 机制 | 适用 | 不适用 | 依据 |
|---|---|---|---|---|
| **r2v**（reference，full-reference 六段式） | 参考图 = 语义条件，逐帧重画 | 台词未定稿、只验构图/动作/运镜的 N10 快出；无强身份约束的空镜/动作镜 | 需要锁脸的正片镜、长段、双人同框 | 手册 N10/N12 原设计；经验库 27.6/27.7 证伪其身份能力 |
| **fl2v**（首帧像素锁，可带尾帧软锚） | 首帧像素锚定，身份从静帧继承 | **身份硬锁的正片镜**（主推）；单人/双人镜按真实首帧配 `EXACTLY-N` | 需要 `<Audio N>` 借音色的段——fl2v 下 source 强制降级 generate，须 ffmpeg mux 回配音 | 经验库 28.11/28.14/28.21F |
| **source**（通用04 fully_copy） | 切段音轨逐字驱动口型 | 台词定稿、要逐句情绪/语速、口型贴真声 | 与 fl2v 同镜时须走 mux 桥接 | 手册 N12 三路底座表 |

**fl2v 三条硬约束（照做，否则返工）**：
1. **首帧字段写相对 input 全路径**：`segments[i].genImage.imageFile` 必须是 `办公室/frames/SHOT-002.png` 这种相对 `input/` 的全路径；只写文件名会报 `Generation segment image could not be loaded`（`load_reference_tensor` 不认 subfolder）。
2. **尾帧是软约束、且必须"人物仍在、构图不同"**：尾帧取 `refs[1]`（从成片 t≈2.0s 抽），与 `genImage` 无关；`torch.equal(tail,head)` 时会被弹回首帧；它只把约束延到 t≈6s，**治本靠拆段**。
3. **refs 只留首帧 + 强负面词**：单人镜 refs 里放双人板 = 必出复制人；fl2v 复制人三诱因是 refs 带身份板／r2v 语义指令残留／负面词弱。`EXACTLY-N` 的 N **必须按 `input/<项目>/frames/SHOT-NNN.png` 真实首帧核对**，不能按剧本文本猜（经验库 28.15/28.22）。

**贯穿铁律 · 拆段**：单段 ≤144 帧（约 6 秒）；实测 ≤124 帧稳、≥209 帧必漂。超长按 `5+17n` 拆两段，B 段首帧从 A 段成片按时间点抽（人物仍在、构图已推进），接缝无跳变、身份更稳，长段漂移 100% 可消除（经验库 28.16/28.18/28.19）。门禁脚本 `h3_lint/check_segment_length.py`（见 N8）。

**fl2v 口型**：fl2v 分支 `ref_audios` 恒 None，嘴型由自生成音轨驱动，与 mux 的配音天然两套——正脸台词镜须再走 LatentSync 后处理（见 N14A）；换语速 = 配音时长变 = 口型产物全部作废，文件名必须带版本后缀。

### N0 · 项目初始化

**目的**：把散落的 skill 产物收敛到一个可回溯的项目根，避免后期 `refs[].imageFile` 找不到文件。

**操作**
1. 建目录骨架：

```
<项目根>/
├─ 01-文本/          novelist + drama 的 Markdown（复制一份，不改原件）
├─ 02-资产/
│   ├─ chars/        角色定妆板 IMG-*-SHEET.png
│   ├─ scenes/       场景板 IMG-*-PLATE.png
│   ├─ props/        道具板、服装站位板 IMG-*-PAIR.png
│   ├─ frames/       vibe 每镜格 SHOT-*.png
│   └─ voices/       音色 REF-*.wav
├─ 03-分镜表/        shotlist.csv
├─ 04-工作流副本/    装配产物 JSON
└─ 05-成片/          mp4 + 归档清单
```

2. 选底座工作流：`工作流底座/H3-通用02-高清主线-参考音色对白-r2v-25step-1344x768.json`（相对主干方案目录；绝对路径见「0. 当前实际路径总表」）（**母版／空白模板**）。
   - 6 个 `H3-EP001-出片-*` 工作流的文件内便签都写着「**由 `H3-通用02-高清主线` 填充生成，勿当模板复用**」——它们是已填好具体镜头内容的**出片实例**，不是模板。
   - 结构实证：通用02 与 EP001 S004 的 13 节点／11 连线、UNET／CLIP／VAE、25step／cfg 1.0／1344×768／res_multistep+simple／shift 12-3、frameRate 24、refMaxSize 1344 完全一致，连 Director 节点标题都叫「EP001 高清版」。差异集中在 `segments` 内容（通用02 = 1 段 124 帧 1 槽占位；S004 = 1 段 102 帧 4 槽实填）与三处底座残留。脚本整体替换 `segments` 并规范化残留，按便签意图用通用02 更规范。
   - **三处底座残留差异**（装配时已处理／说明）：
     - `output.continuityEnabled`：通用02 = **True**、S004 = **False**（S004 便签写「continuity 关闭：各段独立，各自从自己的起始帧起」）。用通用02 当底座，多段连续组默认就开启 22 帧 latent 接力，符合 README 第五节；脚本继承底座值、不擅自改语义。
     - `video.width/height` 与 `global.sourceWidth/Height`：通用02 残留 **960×544**（快出预览尺寸），与 `output` 的 1344×768 不符；S004 是 1344×768。脚本装配时统一同步成 `output` 尺寸。
     - `SaveVideo` 前缀：通用02 = `video/通用_高清`、S004 = `video/EP001_004`。脚本自动改成 `video/<输出副本名>`，避免多组共用前缀互相覆盖；可用 `--save-prefix` 覆盖。

   - 通用01／03 分别是试错与精修档，不作底座。

drama 是 **11 个 skill 组成的套件 + creator-first 五份 Markdown**，不是单一「分镜生成器」。现役版默认落 `剧集/<EP>/`，**不落盘 JSON/JSONL、不建覆盖表**（`docs/comic-drama-workflow.md:37-38`）。

| # | 子技能 | 产物 | 关键字段 / 命名 |
|---|---|---|---|
| 1 | `short-drama-write` | `剧本.md` | `## EP001-SC001 内 · 地点 · 时间/天气`；`[VO]/[OS]/[SFX]/[画面文字]/[连续性]/[转场]`；末尾「声音分层」 |

| 5 | `short-drama-video-prompts` | `视频提示词.md` | `## MOTION-...`；`分镜/时长/生成方式/输入参考图/静态视觉锚点/起始帧/状态链/终点` + `### 可复制提示词`；H3 走六段式 |

| 7 | `short-drama-edit` | `剪辑单.md`、`制作成果/成片/` | 转场、音色登记、`[VO]` 字幕 |
| 8 | `short-drama-review` | `审查/<EP>-审查.md` | 用可见 ID 指向问题 |

**逐镜硬约束**（`short-drama-storyboard/SKILL.md`）：
- 每镜写清唯一职责、来源、时长、景别/机位、运镜、起点、唯一主要动作、终点和声音（`:53`）。
- **有台词镜头必须标 `镜型：SOLO / OTS / DUO`**；`length` 取 **17 的整数倍**（`:135-151`）——这正是 H3 帧网格的来源。**注**：装配脚本另允许 `5+17n`（EP001 实战的 124 帧 = 5+17×7），见 N7；此处保留 drama 原文表述。
- `分镜.csv` 另补 `export_frames`（写帧不写秒）、`音色`、`验收基线`、`refs` 四列供脚本消费。
- 冻结关键帧只写该瞬间**能看见**的内容，不写动作结果（`:152`）。
- 一集关键帧要像同一部片：每条正文用**同一句画风**，每场景同一句光与色温；先出该场景一张中远景作定调图并接受，其余镜头把它作为最后一张参考，只取色调／光线／质感，不取构图（`:154`）。

**槽位语法**（`short-drama-storyboard/SKILL.md:179-185`）：

```
REF-<slot>（顺序：<n>）· <项目相对路径>《<中文名称>》（用途：<用途>；控制：<范围>；不得控制：<范围>）
```

`用途` 只能取九词之一：身份／造型状态／地理／构图／尺度／效果／起始帧／结束帧／风格（`skills/short-drama/references/reference-roles.md:20-30`）。创作者在项目外出图时用 `PLAN-...`，语法相同，只把路径换成 `IMG-...` 或 `SHOT-...` 条目 ID（`:200-203`）。

**门禁**：

```
python <资料库根>/3_漫剧SKILLS/2_分镜/1_主SKILLS/drama-skills-main/drama-skills-main/skills/short-drama-storyboard/scripts/storyboard_lint.py 分镜.md --csv 分镜.csv
```

检查「这一镜交给单轨生成端能不能出声」+ 人物互动站位与视角有无机位语言，以及 `export_frames` 网格、参考图来源、音色/验收基线、打斗三要素、场级节奏。配套 `references/shot-handoff.md` 规定镜间交接：**后一镜的起始帧，必须是前一镜真实结束的那一帧**，同一文件名在前镜 `结束帧` 与后镜 `起始帧` 里路径逐字相同。

**验收**：lint 通过；每个 `REF-/PLAN-` 槽位有 `顺序` 和合法 `用途`；`分镜.csv` 四列齐全；有台词镜都有镜型与音色。

**坑**：`12-H3提示词-官方指南/README.md:107` 记录过一个真实事故——「用『顺序』当身份，顺序就会漂」（SHOT-023 把两个角色的槽位对调了）。修正办法 `README.md:109` 写得很明确：**槽位固定化**，`<Picture 1>` 永远是冻结关键帧、`<Picture 2>` 永远是该角色、没用到的编号留空不重排。本手册 N9 的装配脚本就是按这条实现的。

### N3 · drama → 视觉资产契约整理

**目的**：把 drama 的 Markdown 收敛成「可直接出图」的清单，不让出图环节重新理解剧本。

**操作**
1. 导出出图块：用 `short-drama-image-prompts` 的 `references/asset-export-blocks.md`，把 `视觉设定.md` + `图片提示词.md` 导出为编号块，产物 `剧集/<EP>/导出/asset-blocks.md`，前缀 **C**（人物）/ **S**（场景）/ **P**（道具）。该文件明确是**导出视图**，原项目文档仍是唯一真相，导出块不回写。
2. 逐字带走锚点：人物块的五官／发型／服装段取 `视觉设定.md` 的识别锚点与连续性锁（`:37-40`）；风格前缀统一（`:52`「同一人物的多视角/表情格请用**同一张参考图 + 同一风格前缀**」）。
3. 锁定项目画风：从 `视觉设定.md` 的「项目视觉方向」读取，按 `short-drama-storyboard/references/comic-keyframe-lexicon.md:48-63` 的 8 种基底选一种并写成**可观察**写法：

   | 赛璐璐动画帧 | 厚涂漫画 | 平涂漫画 | 国风条漫 |
   |---|---|---|---|
   | 日系二次元漫剧 | 复古港漫 | 水彩叙事 | 极简叙事漫画 |

   例：赛璐璐 = 清晰轮廓线、平整色块、层数克制的硬边阴影。词表 `:119` 要求按「事实 → 视觉语言投影 → 可读性约束」顺序写。
4. 生成槽位固定表：把每镜的 `输入参考图` 按 `顺序` 列成一张全片统一的表，强制 Picture 1/2/3/4 语义固定。

**输出**：`导出/asset-blocks.md`（C/S/P 块）、`画风基底.md`（一句全片统一画风句）、`槽位固定表.md`。

**验收**：同一个人物在所有 C 块里锚点逐字一致；画风句只有一条；槽位表里 `<Picture 2>` 不出现两个不同角色。

#### 4.1 为什么这一步省不掉

1. **H3 的输入结构强制要求**。r2v 的 `refs` 是 4 个固定槽：`<Picture 1>` 每镜关键帧（vibe 出，每镜换）、`<Picture 2>` 角色板、`<Picture 3>` 场景板、`<Picture 4>` 服装／双人站位板。后三张是**全片固定的身份锚**，与每镜帧是两类东西，vibe 不会顺带产出。
2. **vibe 出每镜格时也要挂它们**。`docs/comic-drama-workflow.md:155` 的原文：「漫剧人物好看但每镜不像同一个人 → 回到 `视觉设定.md` 收紧可见识别锚点；分镜可引用同一 `IMG-...` 提示词条目来对齐意图，但**只有生产 job 的 `references` 实际传入同一图片文件时才共享像素依据**」。`storyboard-sheet-recipe.md:26` 更直接：「**参考图强制入模**：项目里已有角色参考板、地点板等真实图片时，必须作为参考图传给出图模型」。只给文字、不给像素，跨镜必漂。
3. **模型模式表倒推顺序**。`minimax-h3.md:73` 规定「起始帧 + 人物／地点／道具图同时存在 → full-reference 六段式」，`:81-84` 说明首/尾帧与参考输入互斥、整组统一走 reference。也就是说「先有板、后有帧、一起提交」是模型输入结构，不是流程偏好。
4. **工具侧也印证**。09 NG 版 Qwen Image 2.1 的 `+ Figure from a sheet` 要求先把 character sheet 放进 Image card（`_上游文档/GUIDE.md:617-620,634-636`）；只有 `+ Background` 能从文字画空场景。即便想在 ComfyUI 里画每镜格，也得先有角色板。

#### 4.4 走默认本地 ComfyUI 路径时的落地做法

1. 在与 N5 同一个工作流里建 T2I 分支：`UNETLoader`（Qwen-Image 基座 / `Qwen-Image-2512`）→ `CLIPTextEncode`（正向／负向）→ Resolution Selector / `EmptySD3LatentImage`（16:9 ≥1344）→ `KSampler` → `VAEDecode` → `Save Image`。**不要改用 SDXL 底模**：那会与 2511 成为两套模型，违反板帧同源（实现卡 1.3）。
   - **正向** = N3 的 C/S/P 块正文。`asset-export-blocks.md` 的「单块格式」已含风格前缀 + 逐字锚点 + 画幅标注，可原样粘贴，不要改写。
   - **负向** = 块内自带的基线 `text, watermark, extra fingers, distorted face, plastic texture, generic face`（后两项为抗 AI 味词）；动画／古风块追加 `3d render, cgi` 防写实化跑偏，场景空镜可加 `cluttered`。**不要把 `--ar`／`--s` 之类平台参数混进正文**，它们在即梦等平台不生效，只会污染提示词。
   - **画幅**按块尾标注：人物参考板 16:9 横、头像特写 1:1、地点板 16:9。
2. Save Image 的 `filename_prefix` 直接设成 `IMG-<角色>-SHEET` 等，输出目录指向 ComfyUI `input/<项目>/chars/` 等。
3. **同一人物的多视角／表情格必须用同一张参考图 + 同一风格前缀**（`asset-export-blocks.md:52`），不要每个视角重新抽卡，否则板本身就先漂移了。
4. 出图后逐张人工审：脸型、发型轮廓、服装剪裁与颜色、双人站位是否肩并肩（并肩构图会被忠实放大）、有无多余人物／血迹／文字。**这一步是 N11 审片的前移**，在这里改成本最低。
5. 审定后冻结，全片不再换；文件名登记进 N7 的 CSV。

#### 4.5 顺序结论

```
drama 文字设定 → N4 参考板（少量、全片固定、管身份与空间）
                → N5 vibe 每镜格（每镜一张、管该镜起始构图，必须挂 N4 的板）
                → N9 装配（板占 Picture 2/3/4，格占 Picture 1）
                → H3 r2v 一次提交
```

**三类「图」不要混淆**：参考板（进生产、固定）、vibe 每镜格（进生产、逐镜换）、整页 storyboard sheet（`storyboard-sheet-recipe.md:3-5` 明确「**不进生产链、不替代《分镜.md》、不作为任何 `REF-...` 槽位的图片来源**」，路径 `剧集/<EP>/预览/storyboard-<场景ID>.png`，只是给创作者看片子长什么样）。

**网页／App 与 API 是两套收费体系，别混算**：即梦网页端是「每日免费积分 + 会员订阅制」——免费层每日约 60~100 积分、当日清零、默认 720P 带水印；单月购买基础 79 元（725 积分）／标准 239 元（2210）／高级 649 元（6160），连续包月 69／199／499，年付另有折扣；会员权益含「图片 4.0 2K 限时免费」（基础／标准）与「4K 限时免费」（高级）。**积分消耗随模型与清晰度浮动，第三方口径从 1~2 积分/张到 8~16 积分/张互相矛盾，一律以生成前界面显示的预计积分为准**；且积分制「失败也扣积分」。所以批量逐镜与脚本化调用走 API 更划算、重试成本更可控，网页端只适合前 2~3 镜的手工验证。以上价格均为 2026-11-19 公开资料，档位与活动调整频繁，以下单页实时价格为准。

**版本现状**：官方价格页现同时列 `seedream-5-5 / 5-0-flash / 5-0-lite / 4-5 / 4-0`（分别 0.13 起／0.12／0.22／0.25／0.20 元/张）。**按价格 4.0 并非最低**（5-0-flash 0.12、5-5 0.13 起都比它便宜）；`doubao-seedream-4-0-250828` 标记即将下线，若仍用 4.0 首推 `doubao-seedream-4-0-20260415`。**备选引擎**锁定 4.0 的理由是**画风与同源板已按它对齐**，不是价格——**不要因为 5.0-flash 更便宜而中途换模型**，换引擎会破坏 N4/N5 同源定线（方案 4.4.3）。确需换型号时，N4 三张板与全部每镜帧必须一起重出。

#### 5.2 操作

1. 按 `分镜.md` 的 `## SHOT-...` 顺序逐镜生成，**一镜一调、一镜一张**，不画整页漫画。
2. 每镜把 N4 的角色板／场景板／服装板作为参考图传入（像素级身份锚），文字只负责该镜「这一个瞬间」的构图、人物位置、光位、情绪；不写动作结果。
3. 全片复用同一句画风句与同一色温描述；同场景先用一张中远景定调图，其余镜头只取色调／光线／质感，不取构图（`short-drama-storyboard/SKILL.md:154`）。
4. 输出命名 `SHOT-<EP>-<镜号>.png`，落到 `input/<项目>/frames/`；CSV 里写**相对 `input/` 根**的路径（如 `EP001/frames/SHOT-EP001-004.png`）。**A2 已定线弃用 `frames_v4/`／裸板文件名／`refvoice/` 等 EP001 历史命名**，脚本会按三段式路径契约做 ERROR 级校验（方案 5.2）。
5. **不生成对白气泡、字幕、文字、logo**——这些在 H3 阶段由 prompt 与音频层处理，画面里出现文字会被忠实放大。

#### 5.3 drama 提示词的重组规范（不能原样粘贴）

`### 冻结关键帧提示词` 是写给 H3 图生视频的，带 `<Picture N>` / `视觉依据` / `顺序` 等 H3 语义标签，Seedream 与 Qwen 都不认。每镜出图 prompt 按四段重组：

```
[1 身份锚]   C 编号块逐字复制（脸型／发型／服装／辨识物，全片不变）
[2 本镜正文]   该镜「### 冻结关键帧提示词」全文（只写这一瞬间看得见的）
[3 画风句]   项目视觉方向 + comic-keyframe-lexicon 基底，全片同一句
[4 约束]   16:9 横画幅；无对白气泡、无字幕、无文字、无 logo
```

`<Picture N>` 一律改成工具的引用写法（Seedream：`Image 1` / `Image 2`…；Qwen：参考图槽位），并**按 drama `- 输入参考图` 的 `顺序` 固定不重排**；某镜缺图留空槽，绝不前移补位（`12-H3提示词-官方指南/README.md:109`）。

#### 5.4 输出与验收

**输出**：`EP001/frames/SHOT-EP001-004.png` 等（`input/` 根下的相对路径），一镜一张；16:9、输出 ≥1344 宽（默认本地 ComfyUI 由 Resolution Selector 给 1664×928 等 16:9 尺寸；备选 Seedream 用 2560×1440 预设后下采样），不用 9:16。

**验收（起始构图审片）**：谁左谁右、是否并肩、有无多余人物／血迹绷带／现代物品／文字、16:9、≥1344 宽、画风与定调图一致。`<Picture 1>` 的构图 **prompt 压不过它**，画错只能重出图。

#### 5.5 三个必踩的坑

1. **别用「一次 9~15 张组图」代替逐镜**。组图只保证风格与角色一致，画面由模型自行分发，**不保证每镜景别机位精确对应 drama**；而 H3 `<Picture 1>` 是起始构图且 prompt 压不过它，构图错整镜废。组图只适合出同场景的备选／定调图。
2. **参考图分两类，别混淆**：N4 的板（SHEET/PLATE/PAIR，全片固定）是给 vibe 出图当身份锚的；vibe 出的每镜格是给 H3 `<Picture 1>` 的。整页 storyboard sheet 不进生产链（`storyboard-sheet-recipe.md:3-5`）。
3. **画风必须同步**：出的是漫画格，N7/N9 的 negative 里要删掉「卡通／动画感」、改掉真人实拍类描述，否则参考图与提示词互相打架。

> **脚本已落地（2026-11-19）**：先 `--emit-inputs-template out/n5_inputs.json` 生成并填好四段重组材料（drama 冻结关键帧／C 块／画风句不在 CSV 里，脚本不会从 `detailed_description` 臆造起始帧）→ 跑 `python frames_from_shotlist_comfy.py --csv shotlist.csv --inputs out/n5_inputs.json --dry-run` 验四段重组与两 pass 槽位 → 手工在 ComfyUI 跑 2~3 镜（1 对白 + 1 静默 + 1 双人）验证「三张板 + 冻结关键帧」与两 pass 不累积漂移 → 再切 `--server` 批量，产物直落 `input/<项目>/frames/` 并回填 `frame_key`。备选在线引擎用 `frames_from_shotlist.py`。这份 CSV 同时被出帧脚本与 `csv_to_timeline.py` 消费，N4→N5→N9 已闭环；共享逻辑在 `frames_common.py`。

#### 5.6 静帧阶段硬边界与五道门禁（实跑回灌 2026-11-22 · 经验库 19/20.6/24.5）

> 5.0–5.5 是设计态；5.6–5.10 是办公室 15 镜三轮迭代换来的实跑态。**静帧没过门禁不进锁脸，锁脸没过不进视频。** 前一阶段错了，改后一阶段的参数（如 `global.prompt`）属于阶段错位，白耗算力。

**阶段边界（经验库 19.1）**：

| 现象 | 归属阶段 | 正确修法 |
|---|---|---|
| 错误在 `input/<项目>/frames/SHOT-*.png` 已可见 | **静帧/出图阶段** | 改底图/母版/提示词，H3 尚未参与 |
| 静帧对了但视频里几何漂 | 视频 timeline 阶段 | `global.prompt` 场景几何锚（仅语义，锁不住站位，见经验库 18.6） |
| 构图/人数/站位错想靠换脸修 | 阶段错位 | QwenEdit 保构图换脸**只负责换脸**，前提 image1 构图已对 |

**正确顺序**：静帧几何/人数/站位 → 静帧锁脸 → 视频 timeline/global 锚 → r2v 出片。

**静帧五道门禁（经验库 19.5 + 24.5，出片前逐镜人工/ViewImage 审片，独立于视频门禁）**：
1. **人数**：SOLO 镜只允许 1 人，双人镜白名单之外出现第 2 人即 FAIL（纯 T2I 要把 `EXACTLY ONE/TWO people` 写进**正向提示词**）。
2. **几何**：窗/桌/台灯/沙发/门的画面方位与场景底图一致；同场景逐镜复用同一段绝对坐标锚。
3. **资产污染**：画面内不得出现文字、三视图、资产板边框。`*SHEET/*PAIR` 只能作**参考图**传入，绝不能当 `image1` 底图（带文字与排版板会被渲染进画面）。
4. **全身**：人物脚/鞋/地面可见；被桌子遮挡需在提示词层改全身可见，或明确记录为已知妥协。
5. **动作/坐向**：逐镜对照分镜 beat；坐姿写 `seated upright in the chair` 并 negative 掉 `crouching, squatting`，朝向按轴线条款（见 5.9）。

**审片意见先分三层再动手（经验库 20.6）**：

| 层 | 判别特征 | 修法 |
|---|---|---|
| ① 提示词缺失 | 该写的约束没写（朝向/坐姿/相对位置） | 补提示词模板 + negative，成本最低 |
| ② 拆镜设计缺口 | 每条都"正确"但整体错（如 SOLO 规则致全片无同框） | 改分镜标注/拆镜规则，提示词跟着改 |
| ③ 管线/资产问题 | 提示词写全也防不住（纯 T2I 几何漂、底图物理不含目标座位） | 换底图/母版或调参；**重造资产** |

口诀：**提示词执行得越"正确"而整体越错 → 是②不是①**。别在①层反复调词救②③层。

#### 5.7 场景锚板：占用态双母版体系（经验库 23）

**比"空场景底图"更深一层的根因**：底图物理上不含目标座位时，任何提示词/negative 都救不了。办公室底图里桌后无椅子空间、全屋唯一空椅在沙发旁 → 低降噪 img2img 不让改家具几何 → 男主坐最近空椅（桌永远空着），女主被"接近桌子"拉到桌沿反占老板桌。

**正解（占用态双母版，v3 定线）**：
1. **母版 A（看男主）**：机位从客位/门口一侧，男主坐办公桌后**面向镜头**、椅背可见、窗夜景在后。
2. **母版 B（反打）**：机位在男主身后，女主面向镜头在桌旁，男主仅右前景背影虚化（OTS 属正常语法，不算入画人数）。
3. 母版用旧底图 + `denoise=0.90` 让构图彻底重排（继承色调/光线，不继承布局），多种子选优，落 `input/<项目>/scenes/`。
4. 全片逐镜标 A 或 B 并从对应母版派生：单人镜 `0.55–0.62`，双人交接 `0.65`，落位变化见 5.8 档位表。
5. **空场景图只做氛围参考，不得当 img2img 底图**（除非目标构图不需要人在家具位上）——顺序是**先造占用态母版，再造空镜**，不能反。

**坐→站姿态诱发复制人**要显式写 `the chair behind the desk is EMPTY, no one sits at the desk`；纯 T2I 环境词必须收窄 `enclosed private office at night, no other people anywhere`，否则跑成开放大平层+背景员工。

#### 5.8 双人镜与落位：双人底图法 + denoise 档位速查（经验库 22/24.3–24.4）

**失败模式**：空底图 + `denoise 0.72–0.78` 生成双人镜，三种模板（OTS / wide two-shot / 加 `no duplicate, only one woman`）**全部出现第三人**；OTS 写法（"seen from behind in the foreground, softly out of focus"）是最强诱发器，negative 在 0.72+ 压不住人数。

**正解（双人底图法，两段式）**：先拿到一张**人数正确、站位大致对**的双人帧（哪怕构图不完美，如建立镜）→ 当 `LoadImage` 底图，`denoise 0.60–0.66` 二次 img2img 只微调动作/位置（人数已被底图锁定，复制人风险≈0）。单人镜挪落位同理，用同人物已验收帧当底图。

**denoise 档位速查（img2img 实测）**：

| 目标 | denoise | 备注 |
|---|---|---|
| 只换动作/道具，不动人位 | 0.55–0.62 | negative 禁令在此区间有效 |
| 双人交接微调（底图人数正确） | 0.60–0.66 | 双人底图法区间 |
| 改景别（中景→近景） | 0.65–0.75 | 需显式写裁切范围 |
| 挪动落位（到门/沙发等远处） | **≥0.85** + `FAR AWAY from the desk` | 0.72–0.82 被"位置引力"拉回 |
| 坐→站等姿态变化 | 0.78 + `the chair is EMPTY, no one sits` | 否则复制人 |
| 母版重排构图 | **0.90** | 继承色调不继承布局，多种子选优 |
| ECU 大特写 | **脱离底图，纯 T2I** | 底图前景家具会焊死构图 |

> **适用边界**：以上数值是 Z-Image Turbo / QwenEdit img2img 实测；若按 5.1 改用 Qwen-Image-Edit-2511 两级串联，需重新标定具体 denoise，但**三条机制通用**——低降噪锁几何、高降噪改构图、ECU 脱离底图。特写必须写裁切范围 `framing crops at her shoulders, no full body, no desk, background bokeh only`。

#### 5.9 坐向、同框与运镜审查（经验库 20.1–20.4 / 21）

- **SCENE BIBLE 必须含轴线条款**：桌在哪侧、谁面朝哪、正反打两侧各朝什么方向，写进每镜提示词模板，不允许模型自行决定（否则同一人同一桌逐镜朝向跳变、直接越轴）。
- **交接动作镜（递/推/接）一律过肩双人镜（OTS two-shot）**；情绪特写保持单人。同框镜不用多（5/15 即可），但必须覆盖动作交接点——否则 source 档 SOLO 拆镜会导致全片无同框、观众感知不到同一空间。同框镜提示词：`EXACTLY TWO people: 男坐桌后 RIGHT，女 LEFT guest side, both faces visible, no reference board, no collage`。
- **固定机位方向正确，但"固定"不等于"无问题"**：H3 r2v 横移/跟拍/环绕不可靠，节奏靠**景别阶梯**做，不靠运镜做。
- **运镜审查必查五项**：① 空间连续性（人物位置物理连续、光源锚跟空间走）；② 提示词自洽（SOLO 镜禁止不在场对象描写如"影子压在她身上"）；③ 位移幅度（单镜大位移不可靠，改"起始帧已到位 + 动作只走半步"）；④ 景别节奏（高潮升大特写、交接双人镜、建立镜管空间）；⑤ 轴线（正反打朝向固定、同镜不越轴）。
- **多版静帧不可混用**：锁脸版（源自原 T2I）与场景锁版（源自空底图）同一镜朝向可能相反；审片逐版分开，成片只留一条管线产物。

#### 5.10 新场景静帧 SOP 六步（经验库 24.2 复用模板）

1. **先造占用态母版，再造空镜**（见 5.7）；逐镜归 A/B 母版并写明 denoise 档位。
2. **提示词分层固定**：环境头（HEAD）+ 镜头内容（人数/位置/动作/景别）+ 技术尾（TAIL：`photorealistic, 16:9, no text, no watermark` + 人数禁令）。
3. **一镜一调、一镜一张**，全片复用同一画风句与色温；同场景其余镜只取色调/光线，不取构图（5.2 第 3 条）。
4. **生成后逐张 ViewImage 审片**，按标签记 通过/合格/部分/重出，只重出问题镜（旧版先备份）。
5. **顽固项三次降级**：提 denoise → 换底图（双人底图法）→ 脱离底图改纯 T2I。
6. **一镜一问题一改**，不要多个修正塞进同一轮，否则无法归因；审片对照页一律 base64 内嵌，左旧右新。

**三轮迭代教训链（经验库 24.1）**：v1 空底图+低降噪 → 几何统一但坐向跳/无同框；v2 双人底图法 → 坐向一致但底图物理缺陷暴露；v3 占用态双母版 → 构图语义正确、复制人清零（13 通过 + 2 合格）。**前两层调词可救，第三层必须重造资产。**

#### 5.11 静帧锁脸两条铁律（经验库 17/26）

> 静帧几何过门禁后才进本节。办公室 15 帧锁脸终验 15/15 通过；如果你在 r2v 出片阶段还要靠参考板救身份，先读 0.2 的 fl2v 双路线——**r2v 逐帧重画，静帧锁脸也带不进视频身份**。

**铁律一 · 先问"谁的脸真的可见"，再决定锁几段（经验库 26.1）**
- EditPlus 串行两段式（逐人换脸）第二次重绘 **4/4 必劣化**（3 张色彩崩坏、1 张崩成参考板拼贴），劣化 100% 来自第二段，与种子无关。机理：denoise 1.0 全图重绘，二次往返累积色彩漂移。
- **正解**：双人镜里前景背影那人的脸不可见，锁他本就多余——**单段直接锁脸可见者**（终版 15/15 通过、无需两段）；确实两人脸都可见时不要串行，一次调用写明两人（EditPlus 3 槽限制：帧 + 两块肖像板），或走 ReActor 局部换脸。

**铁律二 · inswapper 只换皮肤纹理，换不了身份骨架（经验库 17.3）**
- ReActor/inswapper 换的是**面部纹理**，换不了发型、脸型骨架、耳饰——角色辨识度若靠"长发中分 + 银耳线/高马尾碎刘海"，**锁脸收益极低，不构成有效锁脸**；MD5 变了不等于成功，必须目视。
- 验证换脸生效**必须 `face_restore=none`**：GFPGAN/CodeFormer 人脸增强会改像素，造成"换脸成功"假象。侧脸（3/4 profile）效果更差。
- 参考脸要从资产三视图**裁出单张完整正脸**（额头到下巴 + 双耳 + 无拼图），拼图直接喂会取错脸；双人镜分别换脸用 `detect_gender_input` 分两次串行（female→女参考脸、male→男参考脸）。

**拼贴/参考板入画是种子相关的随机失败**（经验库 26.2）：同提示词此前 14 镜成功、S003 突然出三视图拼贴——**换种子重跑即修**（seed +30000），不必改提示词。用 15 张缩略总览一眼分拣（A 正常 / B 拼贴 / C 色彩失真），不要逐张猜。脚本侧 `连续出图器/锁脸阶段.py` 已固化单人单段、双人单段锁女主、RETRY 换种子机制。

### N6 · 音色资产

**输入**：`剧本.md` 对白 + `分镜.csv` 的 `音色` 列。
**操作**：每个说话人准备一段**干净人声 ≥10s**、无底噪无配乐的 wav；按角色命名 `REF-<角色>.wav`，落 `input/<项目>/voices/`。
**约束**：`Audio: reference` 的段必须挂 `ref_voice`；`Audio: none` 的静默段可不挂。EP001 实战里连静默段也挂了音色（只在 prompt 写 no speech），两种都可行，但**同一项目要统一选一种**。
**坑**：段长必须 ≥ 台词朗读时长，否则音轨被截断；中文负向对 H3 近乎无效，重要禁项写进正向。

**实跑回灌（2026-11-22 · 经验库 14 章）——「有音色」不等于「能直接接上」**：

- **契约是硬约束**：`ref_voice/2/3` 列写的是**相对 `input/` 根的完整路径**（如 `同学会暗恋/voices/REF-LW.wav`），文件名与扩展名由 CSV 写死，不能临时改；声线槽按声明顺序进 `refAudios`，**恒 0 基**（与 `refs` 的 `--ref-base` 无关）。接入前先 `dump` CSV 的 `ref_voice*` 列确认确切字符串，别猜。
- **干净人声的机器粗筛**：`ffmpeg -af silencedetect=noise=-45dB:d=0.20 -f null -` 统计静音段数与占比——纯说话有明显停顿（≥4 段 / >10%），连续演唱或带伴奏接近 0。资产库 18 条 wav 实测静音占比仅 1.5%~4.8%（示例曲/带伴奏），**不采用**；粗筛后仍须人工试听确认无伴奏/底噪。
- **裁净转码规格**：取最长连续有声窗口、居中截 12s（同时满足 ≥10s 与 H3 推荐 5~14s），转 `32kHz / 单声道 / pcm_s16le`；源音频只读不改动。槽位映射（女→槽 0、男→槽 1）留痕到 `voices/音色映射.md`。**换音色只需重跑装配链，不需重出图片**（图片槽与音频槽互不依赖）。
- **⭐「零漂移 FAIL」是误报，别去凑绿**：`csv_to_timeline.py` 生成的 `refAudioStamp`（`index:md5[:10]-size`）用途是同名替换音频时破 ComfyUI 缓存，**不进提示词**。音色从无到有、或换音色，stamp 变化都是**预期行为**，不是内容漂移。判别法：把 `widgets_values[11]` 的 `timeline_data` 做 `json.loads` 拍平字段级 diff，差异应**只有 `/refAudioStamp`**；无音色镜 0 差异、挂音色镜各 1 处。若 `segments`/`refs`/`global.prompt` 有差异才是真漂移。
- **通用铁律**：任何「零漂移/一致性」断言，必须先列**已知合法可变字段白名单**（stamp、时间戳、seed 等）并在对比中剔除，否则会把正确行为误报成回归失败；遇到 FAIL 先做字段级 diff 定位，不要直接改产物去「凑绿」。
- `qc_status` 合法值只有 `通过/已审/pass/ok/PASS`；图审片通过后用**最小文本替换** `待审→通过` 并留 `.bak`，**不跑 `run_test.py` 全量**（其 Stage A/B 会重写上游三件套、冲掉 `frozen_keyframe` 站位锚，见经验库 12.4）。出片前 `--check-only --strict-assets` 应为 0 错误/0 提醒。

### N14A · 配音拟人化与口型对齐（实跑新增 · 2026-11-25 回灌）

> 来源：经验库 28.17B / 28.20~28.30 的 7 轮真实配音迭代。N14 只压句间静默，力度有限；"念台词、有气无力、口型不同步"这些**决定成片质感**的问题在这一节解决。 applicable 场景：需要拟人化配音的台词镜（尤其 `fully_copy` source 镜与正脸口型镜）。

**一、配音"有气无力"的三个真因（按决定性排序）**

| 真因 | 现象 | 正解 | 依据 |
|---|---|---|---|
| **情绪表 key 粒度错配** | 整句合成配分句情绪表 → 7 镜 fallback 纯 calm（男声关键情绪戏全丢） | 情绪表 key 粒度**必须与合成分句粒度一致**；整句合成就配整句 key，或按句读软匹配继承；杜绝 fallback 纯 calm | 28.26 |
| **emotion_audio 锚点含平淡段** | 长锚点（如 15.82s）里大量平淡段被高权重放大，把情绪拉平 | **锚点去留按角色音频特性定，不是全局参数**：男声去掉锚点、纯情绪向量+满权重；女声锚点平淡段少，保留反而稳 | 28.27 |
| **语调起伏被 TTS 压平** | 峰值 RMS/动态与参考接近，但 F0σ 差 30%~2 倍 | 后期用 WORLD 声码器把 F0 曲线绕均值放大 k 倍（时长/音色/停顿不变）；**男声 k=1.6~2.4，女声原版已达标、不要增强** | 28.28~28.30 |

**二、关键参数（实测有效档）**

- 语速：`speech_speed` **语义反转——值越大越慢**。0.72（整句不切）改善自然度；男声最终档 speed 0.62 + weight 1.0 + 向量×1.35，实测 3.7~4.75 字/秒；正常 3.5~4.5 字/秒。
- 停顿：按句号/问号/破折号切块（**逗号不切**，保块内连贯），块间静音破折号 350ms / 问号 300ms / 句号 260ms / 其他 180ms——解决"一句跟一句像念台词"。
- 语调增强：`f0_new = mean + k*(f0-mean)`；k 越大均值会上漂（男声 138→162Hz），且声码器味加重；合成后响度掉到 -19 LUFS，需 `ffmpeg loudnorm=I=-14:TP=-1.5:LRA=11` 拉回。
- **声学靶子纯度检查（方法论铁律）**：用影视/短视频片段当声学靶子必须先查纯度——F0 分布是否双峰、分秒轨迹是否平滑、有声率是否 >70%；配乐/多人会彻底污染 F0σ。抗噪替代指标用**段内 P90−P10 摆幅**（1s 窗口）+ 段间中位 F0 标准差。28.28 的"差 3~4 倍"结论即被配乐污染，28.30 已修正。

**三、口型对齐（fl2v 正脸台词镜必做）**

- fl2v 分支 `ref_audios` 恒 None，嘴型由自生成音轨驱动，与 mux 的配音天然两套——**机制层参数无解，只能 LatentSync 后处理**。
- 输入转 **25fps**（H3 原生 24fps，节点版 24/25 错配）；音频 16kHz mono、apad 补到视频全长。
- **遮罩黑白别写反**：黑(0)=重绘、白(255)=保留；自定义窄遮罩会在对齐空间错位，用原版 `mask.png`（下半脸大椭圆）。
- mux 用 `-map 0:v:0 -map 1:a:0` 防双音轨；`-shortest` 裁尾部静音。只对**正脸台词镜**做，背影/侧背镜靠拆段保人物在画内。
- **版本后缀铁律**：换语速 = 配音时长变 = 全部口型产物作废；输出文件名必须带版本后缀（如 `_v10D`），否则脚本"已存在则跳过"会误用旧口型。

**四、门禁**：正脸台词镜交付前核对——① 情绪表 key 粒度 = 合成粒度（无 fallback 纯 calm）② 语调段内摆幅命中参考区间（男声 P90−P10 49~72Hz、女声 53~65Hz）③ 口型文件名带当前配音版本后缀 ④ 响度 -14~16 LUFS、单一音轨。详见经验库 4.0 / 28.24~28.30。

### N15 · 转场叠化拼接（实跑新增 · 达成"切换不硬"的关键）

H3 出的是 N 段独立 mp4，**段间默认是硬切**。ComfyUI 不生成转场——叠化是拼接阶段用 ffmpeg 加的，
不要试图让 ComfyUI"跑转场"（段间连续性 `continuityEnabled` 默认关、需架构改为单 timeline 全片生成，

  另有 `contact_sheet.py`（联系表）、`transition_ab.py`（A/B/J-cut 对比）。详见经验库 2.5 节。

### N16 · 出片后质检门禁（实跑新增）

- **脚本**：`后期与质检/qc_gate.py`——RMS（开口/句间隔/碎片）+ F0（音色 男≈152Hz/女≈257Hz）自动检测，

`skills/short-drama/references/reference-roles.md:20-30`：身份（只管稳定脸型体态）／造型状态／地理（只管空间关系）／构图（只管占画比例）／尺度／效果／起始帧／结束帧／风格。**一个参考只给一个职责**，冲突参考会让模型在两者之间摇摆。

### 3.5 drama 与「漫画／外部生图」的对接原文

- `docs/comic-drama-workflow.md:19-21`：「视频提示词.md（动态漫剧） └─ 静态漫剧：关键帧切换 + 配音，可跳过」；`:109-110`「只做关键帧切换 + 配音的静态漫剧时，本步可以跳过，**分镜关键帧与图片提示词直接进入生产预览**」。

### 3.6 三 Skill 分工与自动执行协议 ★

到 N2 时三套 skill **按分工自动依次执行**，不是三选一、也不必创作者逐个点名（详见经验库第 29 章）：

| 顺序 | skill | 动作 | 读写面 | 自动? |
|---|---|---|---|---|
| 1 | `short-drama-storyboard`（drama 主干） | 出 `分镜.md` 骨架：镜头职责、连续性、冻结关键帧 | 写 `分镜.md` | 主干 |
| 2 | `导演运镜与机位构图` | 对 `分镜.md` 逐镜跑四查诊断 + 情绪×六维处方，回写机位诊断段 | 读+写 `分镜.md` 的机位字段 | **自动** |
| 3 | `short-drama-video-prompts` | 出 `视频提示词.md` | 写 `视频提示词.md` | 主干 |
| 4 | tudou H3 规则（仅规则+脚本，不装成 Skill） | unit 分段 10–15s、双提示词对位、audio 绑定、上传清单，跑 lint | 读 `视频提示词.md`，出校验报告 | **自动** |

**字段边界（防止互相覆盖）**：导演运镜只改六维与情绪处方，**不动**镜头职责／连续性／冻结关键帧正文／时长；
tudou 规则只管 H3 提示词合规，**不动**分镜边界与台词。两者都靠 `分镜.md` 与 `视频提示词.md` 交接，不改 drama 源码。

**门禁（四重，全过才交 N3）**：步骤 2 后 `check_n2_skills.py` PASS（防忘：漏做导演运镜诊断会点名缺哪几镜并 RC=1）；步骤 1 后 drama `storyboard_lint.py` 0 ERROR；步骤 4 后 tudou lint 0 ERROR；**新增第 4 重 `check_camera_landing.py` + `check_castset_slot.py` PASS**。前三重查"做了没/合不合规"，第 4 重查"诊断有没有落进提示词、景别是否全身、CAST+SET 是否继承"（经验库 30.9 / 31.3 / 31.5）。

> 必配 Skill：`H3跨层一致性锁`（N2 后 / N7 前，管四层事实源五道锁）、`H3成片质量审片`（N10/N12/交付，六维验片）。两者是知识型，由 Agent 主动调用，不改上游文件；方法见各自 SKILL.md 与经验库 31 章。

**"自动执行"的实现机制（务必区分，否则协议落空）**：
- 步骤 2 导演运镜是**知识型 Skill，无 CLI、不能被脚本调用**——由执行 N2 的 Agent 在步骤 1 落盘后、步骤 3 之前**主动用 Skill 工具调用**，创作者无需点名；产物是 `分镜.md` 内【导演运镜诊断】段。这是"语义自动"，不是脚本自动。
- 步骤 4 tudou 是**脚本自动**：`python h3_lint/md_to_h3_lint.py 分镜/视频提示词.md -o out/视频提示词_lint视图.html --lint`，一步出校验视图并跑两个 lint。
- 两者正交：导演运镜写 `分镜.md`（镜头设计层），tudou 读 `视频提示词.md`（H3 契约层），互不改对方字段——**lint 视图是否变化不能用来评判导演运镜是否有效**（T3 实测 A/B 两线 lint 视图字节一致，正确）。
- 防呆：导演运镜只**新增**诊断段，禁止改写 drama 原文；验收=剔除诊断段后与回写前逐字一致（见经验库 30.7/30.8）。

**文档自身的两处小出入**：① 第 153／254 行称 drama-skills 是「12 个技能」，本地现役版实证为 **11 个 skill**；② 第 11 节结论「Vibe 视频不是 ComfyUI」只对代码渲染路线成立，但第 9 节把 ComfyUI + MiniMax H3 的 `infinite-creation` 也列进「Vibe 工具」——说明文档里的 Vibe 是**伞状范式标签**，不是单一程序名。

**给本链路的判断**：若目标是「自己可控、逐镜可审、沿用 drama 五份 Markdown + H3 r2v」，继续按本手册走；若目标是「尽快全自动出片、接受换一套工程」，优先评估 `infinite-creation`（同构度最高）或 `Nomi`（只替换资产与装配层）。二者可混用：用 `infinite-creation` 的资产生成补 N4、N5／N9 仍用本手册的表驱动装配；但**注意它默认用 `Qwen-Image 2.1`（Research License 仅非商用）出图**，商用短剧须按实现卡 1.1 换成 Apache 2.0 的 2511＋基座/2512 组合。

### 6.2 「生成漫画 → H3 导演台」是不是另一条流程（据上传文档复核）

**结论：流程骨架相同，差异不在先后顺序，而在「漫画」的形态与「谁做图生视频」。** 文档里的「生成漫画」实际指向三种终点，只有第一类与 H3 相接：

| 终点 | 文档里的项目 | 产出物 | 与 H3 的关系 |
|---|---|---|---|
| ① 出**静帧／首尾帧**再图生视频 | `infinite-creation`（Qwen-Image 2.1 → **MiniMax H3 Ref2VA**）、`AIComicBuilder` 角色四视图＋逐镜首尾帧、`Jellyfish` 首/尾帧提示词、`Nomi` 一镜一行的「首帧」、`agent-storyboard` 逐镜生成图片 | 每镜 PNG／首尾帧 | **与 N4→N5→N9→N12 同一位置**；`infinite-creation` 就是本手册整条链路的现成实现 |
| ② 出**动态漫画 MP4**（代码渲染） | `vibe-video` 系列、Remotion／`motion-kit`、`story-to-handdrawn-video` 终产物 | MP4 成片 | **与 H3 并列／替代**，不是上游；文档第 11 节「不是 ComfyUI」只针对这一类 |
| ③ 一体化流水线**自带视频模型** | `AIComicBuilder`／`Jellyfish` 完整流程（调 Seedance／可灵／Veo、烧录字幕） | MP4 成片 | **H3 被替换掉**，不再有 `<Picture N>` 与 `timeline_data` |

→ 文档第 11 节「Vibe 视频不是 ComfyUI」与第 9 节把 `infinite-creation`（ComfyUI + MiniMax H3）列为「Vibe 工具」自相矛盾；用户所指的「生成漫画再给 H3」正是第 9 节这条，**它与本手册不不同，是同一条流程的现成实现**。

**但「漫画」不能直接填 `<Picture 1>`，中间必须补一道转换层**（这是唯一实质差异）：

| # | 漫画常见形态 | H3 `<Picture 1>` 契约 | 不处理的后果 |
|---|---|---|---|
| 1 | 整页／条漫／多格绘本 | 每镜**一张**独立起始帧 | 一页多格被当成一格放大，分格线忠实保留 |
| 2 | 竖版／页面比例（`story-to-handdrawn-video` 为 3:4） | 16:9、≥1344 宽 | 非 16:9 被裁切，构图丢失 |
| 3 | 对白气泡、手写体字幕、拟声词、logo | 画面**无任何文字** | 被忠实放大，且与 H3 音频层台词重复 |
| 4 | 角色 Sheet／风格锚／图层部件**内嵌在程序里** | 导出成独立文件挂 `refs` 的 `<Picture 2/3/4>`，**全片固定** | 只留在程序图层里，H3 拿不到像素锚 → 跨镜变脸 |
| 5 | 后期配音／烧录字幕 | 对白镜 `refAudios` + 段尾 `Audio: reference` + 25step | 文档工具多不带音色层，接 H3 需另补 N6 |

**真正的分野是「解耦 vs 内聚」，不是先后**：一体化工具把出图、分镜、图生视频、字幕、合成打包在一个程序里，甚至自带视频模型，drama 的逐镜控制与 `shotlist.csv` 的可重跑性会被它的「智能分镜」接管；本手册把出图与渲染解耦，drama 五份 Markdown／CSV 是唯一真源，出图工具可换，H3 只吃 `timeline_data`。**只借这些工具的「出图／角色资产」半段、后半段仍走 N9 装配 + H3，流程与本手册完全一致**；整套交给它们则等于换工程，H3 导演台被替换。

**落地判断**：想少写代码且保留 H3 → 用 `Nomi`（一镜一行 + 首帧 + 可接本地 ComfyUI）出帧，首帧当 `<Picture 1>`，三张板与音色按 N4／N6 补齐；想全自动 → `infinite-creation` 整条替代（先确认本机 ComfyUI 0.30.2 是否满足）。两者都不改变「先有板、后有帧、板全片固定、帧每镜换」这条输入结构。
