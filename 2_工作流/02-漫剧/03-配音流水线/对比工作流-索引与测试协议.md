# 参考音色对白 · 对比工作流索引与测试协议

> 目的：现有 `IndexTTS2-情感配音工作台.json` 实测「尖 / 飘 / 断 / 碎 / 阴阳怪气」，怀疑根因是 8 维情绪向量与 `emotion_control_weight=1.0` 过火，而非引擎本身不行。
> 本目录保留 5 份**可商用/开源方案**的 ComfyUI 工作流骨架，用于**横向对比**。只提供工作流与安装口径，**不含任何模型、节点包或第三方文件**——模型与节点包由使用者按各文件 Note 节点自行下载安装。
>
> 调研依据：`2_工作流/参考音色生成对白调研.md` + `深度分析-不自然的根因与更优路线_20261126.md` + 各项目官方 README（2026-11 核对）。

## 2. 统一测试协议（保证可比）

### 2.1 固定项——所有方案共用

- **基准台词**：`……好久不见。`（`voice_sheet.example.csv` 的 `VL-001`，试探/轻声/久别重逢）。
- **对白集**（只用于 VibeVoice 多人节点）：`……好久不见。` / `嗯。三年了。` / `你现在做本行了？插画。` / `嗯，勉强算。`（`VL-001`~`VL-004`）。
- **参考音频**：`voices/linwan.wav`（林晚）、`voices/shenyu.wav`（沈屿）。要求 5–15s 干净干声、单声道、无伴奏无底噪；**所有引擎用同一份文件**，不要各录各的。
- **源表演**（仅 Seed-VC 路线需要）：`voices/source_performance.wav`，真人按剧情把基准句演出来，干净人声无伴奏。
- **采样**：输出 wav 统一 48kHz / 单声道后再评；保存前缀统一 `compare/<引擎>_<句ID>`。
- **随机种子**：固定 `42`，每方案至少跑 2 个 seed（如 `42` / `7`）排除偶然。

### 2.2 变量项——只动这一处

| 组 | 改什么 | 不改什么 |
|---|---|---|
| A 基线 | IndexTTS2 现状：`emotion_control_weight=1.0`，八维 `[0.35,0,0,0,0,0.1,0,0.45]` | 台词、参考音频、seed |
| B 减半 | IndexTTS2：`weight=0.4`，八维×0.5 | 同上 |
| C 无情绪 | IndexTTS2：删掉 emotion_vector 连线 | 同上 |
| D Qwen3-TTS | 上排克隆（音色相似度）；下排自然语言语气（只评语气） | 同上 |
| E VibeVoice | 整段对话一次出（评接话节奏） | 参考音频同、台词顺序同 |
| G CosyVoice3 | `instruct_text` 写「自然松弛、真实呼吸、不要播音腔」 | 同上 |
| I VoxCPM2 | `voice_design` 写自然语言音色+语气（架构级对照） | 同上；device 必须 cuda |
| J Seed-VC | 真人源表演 → 换目标音色（`auto_f0_adjust=false`） | 源表演音频与参考音色固定 |
| **K 后期链**（零成本） | 同一份 IndexTTS2 输出，跑「原始 / 后期链 / 后期链+微混响」三版 | 输出音频完全相同，只加后期 |

> **D 组注意**：Qwen3-TTS 上下两排音色本就不同（克隆 vs 预设说话人），下排只评语气自然度，**不要评音色相似度**。同理 I 组（声音设计）也只评语气/连贯度。
> **J 组注意**：Seed-VC 评的是「真人韵律保真度」，音色相似度评的是「换得像不像目标角色」，两者分开打分。
> **K 组优先级最高**：不需要任何新模型，先跑它——若盲听提升明显，说明相当一部分「不自然」是后期缺失而非引擎问题。后期链参数见 `深度分析-不自然的根因与更优路线_20261126.md` 第 3.1 节。

### 2.3 评测指标（四件套）

1. **F0 基频曲线**：用 `librosa` / Praat 看是否出现 227→266Hz 这类异常拔高（经验库 28.10 实测症状）；越平稳、越贴近参考音频越好。
2. **静音比例**：统计句内静音占比。经验库 28.12 实测「断碎」= 静音从 11% 飙到 45%；健康区间应接近参考音频。
3. **盲听 5 分制**：3 人以上、不标引擎名，分别打「音色相似度 / 自然松弛度 / 情绪贴切度」，取均值。情绪贴切度要看**是否贴合语境**（「试探关心」≠「紧张」），不是越夸张越高分。
4. **韵律保真度**（J 组加测）：用 Seed-VC 输出的 F0 曲线与源表演做相关性，越接近 1 说明真人韵律保留越好。

## 3. 判定与落地

- **若 K 组（后期链）就明显改善** → 一半以上「不自然」是 L3 后期缺失，**不动引擎**：把去齿音 + EQ + 微混响固化进 `voice_pipeline.py assemble`（滤镜链见深度分析 3.1 节）。这是零成本、对所有引擎通用的最优先手。
- **若 B/C 组明显改善** → L1 参数过火，**不换引擎**：`voice_map.json` 情绪强度整体减半、`speed` 收到 0.95–1.05、`pause` ≤0.3s、`output_gain` 恒 1.0，音量全交后期 dB。
- **若 I 组（架构级方案）胜出** → 换引擎但只替换 `voice_pipeline.py render` 层，保留 `parse / plan / assemble` 与 19 字段契约；批量仍逐句合成、断点续跑。
- **若 J 组（Seed-VC）在情绪关键场明显最好** → 关键场次改走「真人源表演 + 音色转换」，但这需要人工录制源表演，只适合重点场，不适合大批量台词。
- **若 VibeVoice 的 turn-taking 更自然** → 对白场整段出音，但需另做时间轴对齐（整段节点不逐句给 wav，不能直接喂现有 `assemble`）。
- **生产纪律不变**：台词文本必须与音频逐字一致；`generate` 档参考音色只锁 F0 不锁语速/情绪，要逐句情绪走 `source/TTS` + `fully_copy`。

## 4. 安装与边界（重要）

- **模型 / 节点包一律人工下载**：各 JSON 的 `Note` 节点写明了 `git clone` 地址、模型 HF 仓库与放置目录、`pip` 依赖。本方案**不下载、不安装、不改动任何第三方文件**。
- **节点名 / widget 顺序以实际版本为准**：README 随版本变动；若拖入后节点缺失或参数对不上，按 `Note` 里写的**参数名**在界面手工对应，不要照搬数组下标。
- **许可**：Qwen3-TTS / CosyVoice3 / VoxCPM2 / IndexTTS2 为 Apache 2.0，VibeVoice 为 MIT；Seed-VC 为 GPL-3.0（可商用，衍生代码需开源），且需遵守源音频授权。以各仓库为准。原收录的 Fish Speech S2（Fish Audio Research License）与 Higgs Audio v3（仅研究/非商用）因许可限制已移除，如需研究用途可从 git 历史取回。
- **硬件现实**：Qwen3-TTS 6~8GB、VoxCPM2 约 5GB、CosyVoice3 约 1.5~2GB、VibeVoice 1.5B 约 3~5.4GB、Seed-VC 约 2.5GB；消费级显卡可分别跑。
- **对比顺序建议**：先跑零成本的 K 组（后期链）→ 再跑免费的 B/C 组（现有引擎调参）确认根因 → 再跑 Qwen3-TTS / CosyVoice3 / VoxCPM2 → 情绪关键场专项跑 Seed-VC。

## 5. 调研修正备查

- 调研文档推荐 `Fun-CosyVoice3-0.5B`，但多方实测其情感深度不如完整版/CosyVoice 2.0——0.5B 只是轻，不是最优；以其轻量、易跑作为对比基线合理。
- 调研把「降 temperature/top_p」当通用解，但 IndexTTS2 的主因是**情绪向量与 weight**，不是采样随机性；先动情绪，再动采样。
- IndexTTS2 有第三方实测：不加任何情绪 conditioning 的 baseline 反而最好；`emo_alpha` 降到 0.4–0.5 时多数「尖声」消失；参考音频只有前 15 秒真正生效。
