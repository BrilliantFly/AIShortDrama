# 参考音色对白「不自然」深度分析：根因分层与更优路线

> 承接 `参考音色生成对白调研.md` 与上一轮参数分析。前一轮结论是「大概率不是引擎不行，是参数把演怼满了」，并落地 4 份引擎对比工作流。
> 本轮深挖两个问题：**① 除了换引擎/调参数，还有没有更根本的可能？② 有没有架构层更优化的工作流？**
> 结论：**有，而且最关键的一条不在 TTS 引擎里。** 本轮新增 3 份工作流（Higgs v3 / VoxCPM2 / Seed-VC），与原有 4 份合计 7 份对比样板。

---

## 1. 先把「不自然」拆成三层——不同层要不同解法

之前把所有问题笼统归为「TTS 不自然」，这是误判。实际是三个独立的层：

| 层 | 症状 | 根因 | 对应解法 |
|---|---|---|---|
| **L1 表演层（韵律）** | 尖、飘、阴阳怪气、断碎、没有真人起伏 | 情绪向量过火 / 情绪贴错 / 生成式韵律本身平 | 参数减半 + 语境重贴；或**换自然语言情绪指令**；或**干脆不生成韵律** |
| **L2 音色层（身份）** | 像不像、声音漂、跨句变声 | 参考音频脏、只有前 15s 生效、克隆精度不够 | 换干净 5~15s 干声；换高保真克隆引擎；或 **LoRA 微调专属音色** |
| **L3 后期层（听感）** | 塑料感、干瘪、贴脸生硬、齿音刺耳、忽大忽小 | TTS 出的是「裸干声」，没有录音棚处理 | **后期处理链**：去齿音 + EQ + 微混响 + 响度归一（性价比最高的一刀） |

**关键洞察**：L3 是之前完全没做的一层。`voice_pipeline.py` 的 `assemble` 只做了响度归一（−16 LUFS），**没有去齿音、没有 EQ、没有空间感**。多方实测（Microsoft Azure TTS 文档、播客后期指南、AI 配音实测）一致指出：AI 声音的「塑料感」主要来自频响平直 + 过于干净，一条简单的后期链就能显著改善——**这比换引擎便宜得多，且对现有 IndexTTS2 立即生效**。

## 2. 三条此前没覆盖的根本路线

### 2.1 路线 A：Seed-VC —— 不生成韵律，只换音色（最彻底）

- **思路反转**：前面所有 TTS 都是「文本 → 音色 + 韵律一起生成」，不自然往往出在生成式韵律。Seed-VC 反过来：让真人先按剧情把台词演出来（韵律/呼吸/断句/情绪全是真的），模型只把音色换成目标角色。
- **为什么值得试**：这是唯一能从根上消除「TTS 韵律不自然」的方案——因为韵律根本不是合成的。
- **代价**：需要人工准备源表演音频（`voices/source_performance.wav`），这是额外成本；且源音频必须干净人声，带伴奏会连伴奏一起转换。
- **落地**：`对比-SeedVC-真人韵律保留路线.json`。`auto_f0_adjust=false` 才保留源 F0；目标参考 10~20s 干声。
- **适用场景**：对白情绪要求高、愿意投入真人表演录制的关键场次；不适合大批量路人台词。

### 2.2 路线 B：Higgs Audio v3 —— 情感表达最强 + 内联音效

- 第三方 2026 横评中情感表达排第一（MOS 4.7），100 语言，内联 `<|emotion:...|>` / `<|prosody:...|>` / `<|sfx:...|>` 标签直接控制情感、语速、停顿和笑声/叹气等非语言声。
- **对本项目的针对性**：`<|sfx:sigh|>`、`<|prosody:pause|>` 这类标签正好补上「真人呼吸感」；且强情感标签放开头会漂音色这个坑官方有明确解法（第一个词之后再放标签）。
- **代价**：4B 模型约 9.31GB、11GB 显存；**仅研究/非商用，语音克隆需授权**——商用前必须确认。
- **落地**：`对比-HiggsV3-情感标签与音效.json`。另有 `Higgs v3 Multi-Speaker` 节点可做 2~6 人对话。

### 2.3 路线 C：VoxCPM2 —— 架构级消除「AI 味」

- **直击根因**：传统 TTS 把语音切成离散 token 再还原，语气起伏/呼吸/连读等连续细节不可逆丢失。VoxCPM2 是 Tokenizer-Free，在连续空间直接生成语音表征（MiniCPM-4 + AudioVAE V2，16kHz→48kHz 超分）。
- 中文 CER 0.97%、说话人相似度 79.5%，长段落漏词更少；Apache 2.0；2B 模型，4090 上 RTF 低至 0.17。
- **对本项目的针对性**：如果「不自然」的本质是离散化损失，这条是唯一从架构层解决的方案；且支持「reference（身份）+ prompt（韵律）分开」的 ultimate cloning——正好对应本项目「身份 vs 表演必须分开」的纪律。
- **落地**：`对比-VoxCPM2-连续生成声音设计.json`。注意 device 默认 cpu，必须改 cuda。

## 3. 架构层更优化的工作流：三种「组合拳」

单靠一个引擎解决所有问题不现实。更优的做法是**按层分工**：

### 3.1 优化一：把后期处理链固化进 `assemble`（最高优先级）

现状 `assemble` 已有：逐句增益、停顿/抢话、EBU R128 响度归一。
建议新增（可由 `voice_pipeline.py` 用 ffmpeg 滤镜链实现，无需新引擎）：

```
源 wav → highpass=f=80（去隆隆声）
       → deesser（6~8kHz 压齿音，宽 Q）
       → equalizer（2~4kHz +2~3dB 提清晰度；10~15kHz 轻微 +1dB 空气感；扫频衰减不自然共鸣点）
       → acompressor（温和压缩，ratio 2~3，避免 pumping）
       → aecho/aevalsrc 微混响（room，量 <15%，decay 300~500ms，pre-delay 20~30ms）
       → loudnorm（-16 LUFS 保留）
```

实测口径：干声 / 15% 混响 / 40% 混响三版盲听，8/10 人选 15% 版；混响过量（>30%）会发糊发空。这一步对**所有引擎的输出都有效**，是本轮性价比最高的优化。

### 3.2 优化二：分层选型（不是全剧一刀切）

| 场次类型 | 推荐路线 | 理由 |
|---|---|---|
| 情绪关键场（重逢、争执、流泪） | Seed-VC 真人韵律 / Higgs v3 内联情感 | 韵律与情感是这类场次的命门 |
| 大批量路人/背景台词 | 现有 IndexTTS2 减半参数 或 VoxCPM2 | 便宜、快、够用 |
| 多人对白、needs turn-taking | VibeVoice / Higgs Multi-Speaker | 整段出，接话自然 |
| 音色要求极高的主角 | Fish S2 / CosyVoice3 Instruct2 / Qwen3-TTS | 克隆精度 + 自然语言情绪指令 |
| 最终交付兜底 | ElevenLabs Text to Dialogue（付费） | 顶级自然度，成本换确定性 |

### 3.3 优化三：身份与表演的「双轨制」

本项目已有纪律「身份靠参考音频、表演靠 prompt」。VoxCPM2 的 ultimate cloning（reference 管身份 + prompt 管韵律）和 Higgs v3 的「reference_text 显著提升克隆质量」都印证这条路。建议下一步在 `voice_map.json` 里为每角色存**两条**参考：一条身份参考（固定音色）、一条表演参考（韵律样本），而不是现在的一条混用。

## 4. 更新后的完整对比矩阵（7 份工作流）

| 工作流 | 层 | 解决什么 | 显存 | 商用 |
|---|---|---|---|---|
| `IndexTTS2-情感配音工作台.json` | L1/L2 基线 | 现状对照 | 中 | 可 |
| `对比-Qwen3TTS-声音克隆.json` | L1+L2 | 自然语言情绪指令 vs 8 维向量 | 6~8GB | Apache 2.0 |
| `对比-VibeVoice-双人对白.json` | L1 对白 | turn-taking 自然度 | 3~5.4GB | MIT |
| `对比-FishSpeechS2-内联情绪标签.json` | L1+L2 | [tag] 内联情绪、高保真 | 12~24GB | **受限** |
| `对比-CosyVoice3-Instruct2情绪指令.json` | L1+L2 | instruct_text 自然语言引导 | ~4GB | Apache 2.0 |
| `对比-HiggsV3-情感标签与音效.json` | L1 情感 | 情感表达 MOS 4.7、内联音效 | ~11GB | **仅研究** |
| `对比-VoxCPM2-连续生成声音设计.json` | 架构 | Tokenizer-Free 消除 AI 味 | 中 | Apache 2.0 |
| `对比-SeedVC-真人韵律保留路线.json` | 根治 L1 | 不生成韵律只换音色 | 中 | 遵守源音频授权 |

**新增评测维度**（在原三件套基础上）：
- **L3 后期增益测试**：同一段 IndexTTS2 输出，跑「原始 / 后期链 / 后期链+微混响」三版盲听，验证 L3 到底占多少分。
- **音效/非语言声**：Higgs v3 版额外看笑声/叹气是否自然、是否掩盖了 TTS 味。
- **韵律保真度**：Seed-VC 版用 F0 曲线与源表演做相关性，越接近 1 说明真人韵律保留越好。

## 5. 推荐执行顺序（本轮新增后的修正）

1. **先做零成本验证**：用现有 IndexTTS2 输出跑 L3 后期链 A/B（不需要任何新模型）。若盲听提升明显，说明一半以上的「不自然」是后期缺失，不是引擎问题。
2. **再跑轻量引擎**：Qwen3-TTS / CosyVoice3 / VoxCPM2（自然语言情绪指令 + 架构级方案），统一用 `……好久不见。` 基准句。
3. **情绪关键场专项**：Higgs v3（情感 MOS 4.7）与 Seed-VC（真人韵律）二选一或都测，看哪个更贴「试探关心 ≠ 紧张」这类语境。
4. **最后看硬件决定**：显存 ≥20GB 再上 Fish S2；商用项目排除 Fish S2 / Higgs v3。
