## 一、结论摘要

### 1.1 库内重复：没有真正的重复

| 检测层级 | 判定方法 | 结果 |
|---|---|---|
| 字节级 | 31 个文件 MD5 两两比对 | **0 组**，全不相同 |
| 拓扑级 | 节点类型多重集 + 连线数 | 3 组同构族，均为**故意设计的模板族** |
| 功能级 | 归一化指纹（抹掉提示词/路径/种子/输出目录） | **2 对完全等价**：`28张-01≡28张-04`、`28张-02≡28张-03` |
| 参数级 | 逐节点 widget 差异 | 其余近邻对均有实质差异，不构成重复 |

### 1.2 库外重复：这才是问题所在

资产库与 ComfyUI 实际工作流目录做交叉比对后：

- **31 个文件里有 28 个与 ComfyUI 目录中的文件字节完全相同（MD5 一致）** —— 资产库本质上是一份镜像，不是独立资产。
- **ComfyUI 目录内部自身还有 6 组重复**：
  - `H3-通用01/02/03/04` 同时在 `01-通用-H3\` 与 `通用合并版\` 各存一份 → 加上资产库共 **3 份**
  - `IndexTTS2-声音克隆-v1` 在根目录有 `IndexTTS2-声音克隆-v1.json` 与 `音频-IndexTTS2-声音克隆-v1.json` → 共 **3 份**
  - `MiniMax_H3_Continuum_V38X2` 与 `MiniMax_H3_Continuum_V38X2+Decode_Cache_Helper` 字节相同（就是 README 提过的那个经典重复）→ 共 **3 份**
- **只有 3 个文件是资产库独有的**，ComfyUI 目录里没有：
  `H3-Multiframe参考-武侠武打-25step`、`-4step`、`H3-FunControlNetUnion-动作迁移-r2v-25step`
  → 反过来说，**这两个最需要 ComfyUI ≥ 0.33.0 的新工作流，在 GUI 侧边栏里根本打不开**。

### 1.3 一句话

库内干净、库外三份。真正该做的不是"删重复工作流"，而是**定一个唯一主目录**，把 `01-通用-H3` 与 `通用合并版` 这对双胞胎、IndexTTS2 的双份、V38X2 的 Decode_Cache 副本清掉，并把 Multiframe/FunControl 三个独有文件同步进 GUI 目录。

## 四、库内重复检测明细

### 4.1 功能级等价：只有「28张」族内部两对

抹掉提示词、种子、图片路径、输出目录后重算指纹，出现两对零差异：

- `28张-01-角色板-1344x768` ≡ `28张-04-场景板-1344x768`（画布、8 步、cfg 1.0 全同，只有 prompt 与 `filename_prefix` 不同）
- `28张-02-人像正面-832x1216` ≡ `28张-03-人像侧脸-832x1216`（同上，只有 prompt 不同）

判定：**同一模板的 4 个提示词实例**，不是 4 个工作流。当"板卡生产线"用很顺手，但对"工作流库"来说 5 个文件只能算 3 种规格（1344×768 / 832×1216 / 1024×1024）。

### 4.2 只差 taskType：5 个导演台模板

`r2v / rv2v / v2v` 三份逐节点比对的唯一功能差异是 Director 节点第 0 个 widget（taskType 字符串）；`t2v / fl2v` 同理。即：**5 个模板 = 2 种权重组合（ref2va / fl2va）× 若干下拉值**，理论上 2 个文件够用。

判定：**可接受的冗余**，保留 5 个入口对查找更方便，但要知道它们本质同一张图，改参数时别只改一个。

### 4.3 高重叠但确有分工（保留）
