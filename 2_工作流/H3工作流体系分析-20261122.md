## 二、与官方模板的关系（节点级实证）

### 官方模板（04-H3-官方模板）

- 29 节点 / 23 种节点类型，MiniMax 官方发布的**原始参考实现**。
- 用 ComfyUI 原生节点手工搭出完整采样循环：`RandomNoise → BasicGuider + BasicScheduler → SamplerCustomAdvanced`，核心专用节点为 `MiniMaxH3ReferenceToVideo`。
- 外围有 `ComfySwitchNode`（模式开关）、`ResolutionSelector`、`ComfyMathExpression`（帧数换算）、`LoraLoaderModelOnly` 等。
- **所有底层参数裸露可调**：sigma、shift、步数、LoRA、分辨率。它是一切参数口径的"出处依据"。

### 导演台通用（01-H3-导演台通用）

- 11 节点 / 8 种节点类型：`UNETLoader + CLIPLoader + 2×VAELoader + MiniMaxH3Director + CreateVideo + SaveVideo + MarkdownNote + 3×PreviewAny`。
- 本质是把官方 29 节点**封装成一个 `MiniMaxH3Director` 节点**，采样循环、模式切换、帧数换算全部进节点内部，外围只留加载与出片。
- 参数值继承官方模板：25 步 / cfg 1.0（走 BasicGuider 无 CFG）/ res_multistep + simple / shift 12（视频）·3（音频）/ 1344×768 / ref_max_size = 宽度。
- 一次 Run 约 15s 上限，多段镜头靠手动拼接。

### 漫剧生产卡（02-漫剧/02-H3漫剧流程）

- 在导演台封装之上叠加**生产要素**，合并自归档 EP001 实战卡与二采底座：
  - 参考音色对白：段尾 `Audio: reference`，音色锁定 + 口型由 AV latent 自动驱动（4 步 generate 语音语义崩坏实测：有声音听不懂，对白镜禁用 4 步）；
  - continuity 22 帧接力：多段必须一次提交（`--shots 1,2,3`），latent 接力才不断；
  - segments 导出：成片落在 `output/minimax_seg_export/<时间戳>/seg_XXXX.mp4`；
  - 二采精修链：`MiniMaxH3DirectorRefine`（refine_model + beta/3/0.2 调度）。

**一句话**：官方模板是"教材"，导演台是"封装工具"，漫剧三卡是"量产模具"。

### 派生关系修正（2026-11-22 节点级核验）

**"基于官方"要拆成两层说，不能笼统讲"所有导演台都基于官方版制作"：**

1. **模型层：是。** 所有导演台跑同一个 H3 官方模型（minimax_h3 权重），采样口径复刻官方参考实现（BasicGuider 无 CFG、res_multistep+simple、shift 12-3、`5+17n` 帧网格）——这是它们能对齐的根基。

2. **工作流层：不是。** 各导演台**不是**拿官方模板 JSON 改出来的，而是**四家各自独立实现的节点包**。实测各套 H3 核心节点：

| 套 | H3 核心节点 | 归属 |
|---|---|---|
| 官方模板 | `MiniMaxH3ReferenceToVideo` | ComfyUI 内置官方原语节点 |
| 导演台通用（AIMixer） | `MiniMaxH3Director` | 第三方自研节点包（单节点封装整个采样循环） |
| 二采加速 | `MiniMaxH3Director` + `MiniMaxH3DirectorRefine` | AIMixer 系扩展 |
| 漫剧高清主线 | `MiniMaxH3Director` + `MiniMaxH3MemoryEfficientSageAttentionPatch` | AIMixer 系 |
| NG版（seesee75） | `NGH3Director` | seesee75 自己的节点包 |
| Timeline（Songssx） | `MiniMaxH3TimelinePlanner` + `MiniMaxH3FiniteSegmentSampler` | Songssx 自己的节点包 |
| T8曜石 | `MiniMaxH3DirectorProjectT8` | T8 自己的节点包 |

- 官方模板是"参考实现"（原生节点手搭采样循环，教学/基线价值）；
- AIMixer 导演台把官方循环**重封装**成一个节点——这条线与官方模板血缘最近，漫剧三卡又从它派生（JSON 级派生关系只存在于这一支）；
- NG版 / Timeline / T8 是三个独立开源项目，各有自己的采样器/规划器节点，**与官方模板 JSON 没有派生关系**，只共享官方模型与采样口径。

**结论**："所有导演台共用同一个官方 H3 模型和采样口径"成立；"所有导演台工作流都基于官方模板制作"**不成立**——仅 AIMixer 导演台（→漫剧三卡）这条线存在 JSON 级派生。第一节的"关系总链"箭头仅适用于 AIMixer→漫剧这一支，09/10/11 三套应视为与官方模板平行的独立实现。

## 三、各套功能作用特色

### 04-H3-官方模板（3 张：t2v / i2v / r2v）

- 定位：参考实现 / 参数基线。
- 特色：唯一能看到完整采样循环与全部底层参数的地方；排查画质问题（糊、灰、伪影）时回这里对照"官方口径"。改 sigma/采样器前先查它。
- 现状：只作对照，不直接参与生产。

### 01-H3-导演台通用（7 张）

- 定位：封装版母版（AIMixer 系）。
- 覆盖 6 种输入模式：t2v（纯文本）/ r2v（参考图，⭐漫剧主力）/ rv2v（参考图+视频）/ v2v（视频转视频）/ fl2v（首尾帧）/ external_groups（外部分组版 i2v、r2v）。
- 特色：11 节点极简拓扑（吸收自"加速版清理版"），节点图一眼读完；多段手拼适合短片段。
- 现状：漫剧三卡的直接母版；新输入模式需求先来这里找。

### 02-漫剧·通用三卡（现役生产线）

- `H3-通用01-快出预览-r2v-4step-960x544`：4 步试错（构图/运镜/prompt 调优），单段 2~4 min；无对白空镜可直交付。
- `H3-通用02-高清主线-参考音色对白-r2v-25step-1344x768`：正式出片，15~25 min/段；对白镜头挂参考音频锁音色，口型自动对齐。
- `H3-通用03-二采精修-refine-25step-1344x768`：关键镜头加档精修，25~40 min。
- 日常节奏：**01 试错 → 02 出片（对白挂参考音色）；关键镜头升级 03**。
- 已沉淀实战边界：4 步对白崩坏、段长 ≥ 台词朗读时长、prompt 一致触发整图缓存、SaveVideo moov 延迟、44.1kHz=source 生效 / 32kHz=generate。

### 02-H3-二采流水线（1 张）

- 定位：二次采样精修链底座。
- 特色：`MiniMaxH3DirectorRefine` 二采链（refine_model + BasicScheduler beta/3/0.2），已吸收进漫剧通用 03。upscale 模式需 `minimax_h3_latent_upscaler_3d_*.safetensors`（未下载，用户手动）；默认 refine 模式不需要。
- 现状：已派生，底座保留。

### 03-H3-Continuum（3 张，实验性）

- 定位：时序延续的早期探索（V38X2 → V39 两代、三种变体）。
- 特色：latent 级续接思路的雏形。
- 现状：实验品，路线已被 10-Timeline 的"AV Latent 直接续接"超越；留档对照。

### 05-H3-Multiframe参考（2 张）

- 定位：特种·多帧动作参考（打斗戏）。
- 武侠武打 25step-1344x768（出片档）/ 4step-864x480（预览档）。
- 现状：打斗镜需要动作参考时取用。

### 08-H3-FunControlNetUnion（1 卡 + 脚本组）

- 定位：特种·动作迁移。
- 特色：人物照另一段视频的动作演（Pose/Edge/Depth/遮罩），FunControlNetUnion + r2v 25 步；配套自动武打流水线（`auto_fight_pipeline.py` 打段、`detect_action_cuts.py` 切镜检测、`make_action_clips.py` 成段、`shots.template.csv` 模板）。
- 现状：动作镜/武打流水线时取用。

### 09-H3导演台-NG版（seesee75，10 张）

- 上游 `ComfyUI-MiniMaxH3-Director` v1.0.1（GPL-3.0，~350★），收录 2026-11-16。
- 定位：二代导演台——**原生 Loop 自动切段 + 自动续接**，不用手拼。
- 10 模板覆盖：文生三镜、角色与声音（跨段保脸）、音乐视频锁歌（Whisper 对歌词）、每镜首帧钉图、每镜出静态图（分镜板）、双角色故事板、Pose 驱动控制视频、遮罩 Inpaint 换人、自定义采样、Legacy 时间线。
- ⚠️ 门槛：**ComfyUI ≥ 0.37.0**（本机 0.30.2，打开大面积红框，仅 Legacy 能跑）；H3 全家桶权重约 60 GB；16GB 显存 1280×704 + Turbo LoRA 可跑。
- 现状：等 ComfyUI 升级后启用；模板打开时示例素材自动拷入 input/（前缀 h3-example-）。

### 10-H3导演台-Timeline（Songssx，4 张）

- 上游 `ComfyUI-MiniMaxH3-TimelineDirector` v0.6.0（GPL-3.0，~770★），收录 2026-11-16。
- 定位：**技术路线最先进的续接方案**——上一段采样出的 AV Latent 尾部直接喂下一段，不经过解码→重编码，接缝从源头掐掉大半；再叠 Drift-Control 遮罩 + Soft AV 半余弦音频过渡。
- 一套图覆盖 7 类任务（切素材/拉 GEN 框/写 prompt 即可，连线不动）：文生、参考图、图+音频、数字人对口型（原音锁定）、视频可编辑参考、人物替换、动作迁移。
- 关键参数（照抄勿算）：帧长 `5+17n` 网格（124 帧≈5s@24fps）；重叠对齐（请求 24→实际 22、请求 48→实际 39）；每段同 seed；分段上限 64。
- 视频素材三种用途：固定 Guide（续写保运动）/ 可编辑参考（换人换风格）/ 仅固定边界。
- 04 号模板可配 Omni 多模态自动扩写提示词。
- ⚠️ 同样受 ComfyUI 版本门槛限制。

### 11-H3导演台-T8曜石（节点包 + 网页导演台）

- 上游 `comfyui-minimax-h3-audio-T8`，收录 2026-11-16。
- 定位：**不是一套工作流，是 14 节点包 + 独立 UI 导演台**（跟 ComfyUI 画布并列的网页工作台：左镜头列表 / 中提示词 / 右素材区）。
- 本库收录六组：Starter 入口、已审配方 4 张、剪辑 Studio（时间线/A-B 对比/选择性修复/交付）、长片续接 46 文件、视频外扩九步闭环、语音对白参考音色 18 文件；另有 100 类 3228 个示例 JSON 全量 zip（找冷门配方时翻，勿整包解压）。
- 工程化能力（最值钱）：按顺序生成失败即停、A/B 同镜对比"采用此版"、取帧接下一镜、独立 CPU FFmpeg 导 MP4、工程包 ZIP 跨机、双采样两阶段 LoRA 链、文本分镜导入（`# 镜头名 | 时长`）。
- 三种素材用途：原音驱动（口型+原声交付）/ 参考音色（新音色念新台词）/ 视频自带音轨；提示词 `@` 引用素材。
- 现状：需装插件后启用；入口 JSON 是干净模板，先换模型素材再跑。

## 五、三维度对比：漫剧质量 / 人物口型 / 配音（2026-11-22 补充）

> 前提：全家族共用官方 H3 模型（原生 768p），质量上限相同，差距来自步数/分辨率/LoRA/接缝；H3 音视频联合生成，**口型由音频 latent 驱动，口型好坏取决于"音频从哪来"**。

### 5.1 漫剧质量

| 工作流 | 质量档 | 说明 |
|---|---|---|
| 漫剧通用02 高清主线 | **第一档·量产标杆** | 25 步全量去噪 + 无 LoRA + 1344×768 原生精确落点 + ref_max_size=宽度 |
| 漫剧通用03 二采精修 | 第一档+ | refine 模式细节增强；upscale 模式需 latent upscaler 权重（未下载） |
| 官方模板 25 步档 | 第一档 | 参数基线，高清主线参数即继承于它 |
| Timeline 01 | 第一档~ | 25 步档 + **latent 直接续接接缝最小**，长片一致性最好 |
| T8 双采样配方 | 第一档+（潜力） | 底模两阶段 LoRA 链 + 学习型 3D latent 放大 |
| NG版 | 中~第一档 | 1280×704 + Turbo LoRA 实测可跑；挂 turbo 细节略降 |
| Multiframe / FunControlNetUnion | 中（动作优先） | ControlNet 换动作正确性，画面自由度受限；武打镜专用 |
| 4 步档（通用01、武侠4step） | 预览档 | 只配试错与无对白空镜直交付 |
| Continuum | 实验 | 接缝不如 Timeline，留档 |

单镜质量各家都能到 768p 官方上限；**量产稳定性漫剧三卡最强，长片一致性 Timeline 最强，精修上限 T8 双采样/二采 upscale 最高**。

### 5.2 人物口型

| 路线 | 口型可靠性 |
|---|---|
| **source 原声直通**（配音流水线→mux；归档对白原声卡） | **100%**——原声在音轨里，口型逐字吻合 |
| **generate + `Audio: reference`**（漫剧高清主线，25 步） | **高**——20/25 步语音成形，口型由参考音频 AV latent 自动对齐；**4 步禁用** |
| Timeline 数字人对口型（原音锁定，AV latent 逐段注入） | 高且**长片最稳**——Soft AV 过渡，跨段口型不跳 |
| T8 原音驱动 | 高——独立录音驱动口型并按原声交付 |
| NG版-02 角色与声音 | 中高——跨段保嗓音；NG-03 锁歌 Whisper 对歌词时间轴 |
| 4 步 generate | **不可用**——语音语义崩坏，口型必乱 |
| 后期兜底：LatentSync 口型对齐（归档） | 单段重对齐，救已生成错的片 |

### 5.3 配音

| 方案 | 能力 |
|---|---|
| **03-配音流水线（IndexTTS2）** | **表演控制最细**：逐句合成、八维情绪向量、语速 0.25~4.0、逐句增益（−9~+5dB）、句间停顿/抢话负值重叠、seed 可复现；身份与表演分离。短板：节点包+模型未装 |
| 漫剧高清主线（generate 参考音色） | 现役主力：台词逐字写 prompt、改词即重跑；短板：情绪/语速粒度粗，段长必须 ≥ 朗读时长 |
| T8 05-语音对白 | 双人对白、原声锁定音床、长文分段、重混；参考音色念新台词不承诺声纹完全一致 |
| NG版-02/03 | 跨段保嗓音；锁歌 MV 特化 |
| Timeline | 只收音频参考/原音锁定，无 TTS 层 |
| 官方模板 / 导演台通用 | 无配音能力 |
| 07-IndexTTS2 声音克隆底座 | 单句克隆基础卡（配音工作台的底座） |

### 5.4 推荐搭配

**目标 A：只要漫剧质量高（不管配音口型）**

- **首选：漫剧通用三卡**（01 试错 → 02 出片 → 关键镜头 03 精修）。量产最稳、边界经验最全。
- 冲击上限：02 出片后对关键镜头加 03 二采；装上 latent upscaler 权重后 upscale 模式再上一档。
- 武打/动作戏：Multiframe 或 FunControlNetUnion 特化，其余镜头仍走三卡。

**目标 B：漫剧质量高 + 口型准 + 配音语速自然、有感情（三优）**

- **首选组合：配音流水线（IndexTTS2）→ H3 source 档 mux**
  1. `voice_pipeline.py parse/plan`：剧本 → 配音本，自然语言 cue → 情绪/语速/音量结构化参数（**语速自然**：TTS 层 speech_speed 逐句控，急促 1.2 / 正常 1.0 / 缓慢 0.85；**感情**：八维情绪向量逐句配，与 ≤1.5）；
  2. `render`：逐句合成（seed 由 line_id 派生，可复现）；
  3. `assemble`：按时间轴拼装——换人接话 0.35s / 抢话 −0.2~−0.5s 重叠、逐句增益、响度归一；语速仍不满意用 `--post-speed`（仅现成 wav 场景）或后期 `audio_tighten.py` 压句间静默；
  4. H3 **source 档**：原声 mux + 口型贴原声逐字吻合 → **口型 100%、配音表演全可控、质量走 25 步档不受影响**。
  - 前置：装 ComfyUI-IndexTTS2 节点包 + IndexTeam/IndexTTS-2 模型（README 第三节，手动下载）。
- **备选 B'：全 generate 一条龙（不装 TTS）**——漫剧通用02，台词逐字写 prompt + 段尾 `Audio: reference`。优点：零新依赖、改词即重跑；缺点：情绪/语速只有整段粒度，"语速自然+感情"上限低。
- **备选 B''：Timeline 长片路线**——latent 续接 + 原音锁定，跨段口型一致性理论最优；配音表演粒度同 B'（粗），适合长对白连续剧场景，待实测。

**目标 C：其他搭配速查**

| 场景 | 搭配 |
|---|---|
| 无对白动作/空镜快交付 | 通用01 4 步直出 |
| 唱歌/音乐 MV 口型 | NG版-03 锁歌（Whisper 对歌词） |
| 双人对白工程化（A/B 采纳、顺序生成） | T8 05-语音对白 + 剪辑 Studio |
| 口型已翻车的成片补救 | 归档 LatentSync 单段口型对齐 |
| 长片连续生成（多段不跳） | Timeline 01（待实测对比 continuity 22 方案） |

**结论**：三优目标下，**配音流水线 + source 档 + 漫剧 25 步档**是唯一同时拿满三项的搭配；它把"口型"从生成问题变成"原声直通"问题，把"语速/感情"从整段粒度细化到逐句粒度，质量维度不受任何损失。代价只是装一次节点包与模型。

## 六、落地推荐方案：配音流水线 → 25 步 source 档（2026-11-22）

针对目标 B（质量高 + 口型准 + 配音语速自然有感情），结合现状差距，给出分阶段落地方案。

### 6.1 现状差距（为什么要分阶段）

- **配音侧**：`02-漫剧/03-配音流水线/` 已入库（voice_pipeline.py 四段流水线 + 情感配音工作台卡），但 **ComfyUI-IndexTTS2 节点包与模型未装**（清单见其 README 第三节，按约定用户手动下载）。
- **出片侧**：现有 source 卡只有归档里的 `H3-通用02-对白原声-source-4step-1152x640.json`（4 步 turbo + 1152×640 旧档，上游标注"已弃用"），**没有 25 步高清拓扑的 source 卡**。
- **结论**：链路设计已闭合，缺"装包 + 一张新卡"两步。

### 6.2 推荐方案：三步走

**第一步（立即可做）：装包跑通配音侧**
1. 安装 ComfyUI-IndexTTS2 节点包（命令见配音流水线 README 第三节），下载对应模型权重；
2. 用 `voice_pipeline.py parse → plan → render → assemble` 跑一次 voice_sheet.example.csv，产出整场对白音轨 + 对白时间线.csv；
3. 验收：试听逐句情绪/语速是否符合 cue，时间线 csv 与音频逐句对齐。

**第二步（核心改造）：产 25 步 source 档新卡**
- 改法：把归档 source 卡的 `audioMode=source` + prompt 尾部 `Audio: fully_copy` 移植到漫剧通用02（高清主线）的 25 步拓扑上，参考音频槽改挂配音流水线产出的整场音轨（按对白时间线.csv 切段）；
- 产出新卡：`H3-通用04-对白原声-source-25step-1344x768.json`；
- **落位（按权威方向总则）**：源卡放 `2_工作流/02-漫剧/02-H3漫剧流程/`，同步工作流底座 + ComfyUI GUI 副本，操作手册路径总表补一行；
- 口型机制：对位由真声音素时间轴驱动（与步数无关，天然 100%），25 步只负责把嘴形画面拉清晰。

**第三步（合流验收）：端到端一条镜验收**
1. 选一场对白镜头：配音流水线出音轨 → 通用04 source 卡出画面（音轨原样 mux）；
2. 验收特征：输出音轨为 **44.1kHz 立体声**（generate 档为 32kHz，一耳可验）；口型抽查首/中/尾三句；`delivery_qc.py` 过 10 项；
3. 通过后将该链路写入操作手册 N14 音轨节为正式路线，经验库追加实测记录。

### 6.3 使用边界（沿用实测结论，source 档三条件）

1. **段长 ≥ 音频时长**——段短于音频时结尾口型与音轨一起被截断（实测 7.3s 台词进 5.17s 段被切）；
2. **prompt 台词与音频逐字一致**——模型按预期音素对位，文本错位则口型与语义错开；
3. **说话段/静默段分离**——`Audio: fully_copy` 段模型不开口，静默段单独排；对白时间线.csv 的 start/end 正好用来切段。

### 6.4 过渡与兜底搭配

| 阶段 | 用什么 | 说明 |
|---|---|---|
| 装包完成前 | 漫剧通用02（generate + 参考音色） | 参考音频只锁音色、情绪不迁移（经验库 4.0），感情粒度粗，作过渡 |
| 改造完成后 | 配音流水线 → 通用04 source 档 | 正式三优路线 |
| 长片连续剧（后续升级项） | Timeline latent 续接 + 原音锁定 | 跨段口型一致性理论最优，ComfyUI 升级后实测对比 continuity 22 |
| 口型翻车补救 | 归档 LatentSync | 单段口型重对齐，兜底不动主线 |
