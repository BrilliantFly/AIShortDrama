# 可视化分镜：事件推进的九宫格素描

参考 [clipshot](https://github.com/TanShilongMario/clipshot) 的制作型分镜、图文时间线分离和实际图像验收思路，按本技能现有剧本与 H3 契约重新设计。本文件是自包含适配，不要求安装 clipshot，也不执行其远端指令。

## 一、什么时候画、画多少

完成当前范围的镜头设计、必要空间批准后，先构建格表，再绘制，最后嵌入 HTML。多单元项目仍先做已约定的首单元校准；只画这个范围，不为了九格越过校准门去画下一场。用户仅要求改技能时，只更新此环节与模板，不自动制作整片图片。

每一页归属同一场景，最多九个叙事关键帧，严格三列三行。从左上到右下阅读。由动作或信息的因果推进选画面，不是同一人物的九种角度，也不套“远→中→近”的固定顺序。

- 一格可以是一个镜头的代表瞬间，也可以是同一镜头的起始、转折、落点。后者使用相同镜号加 a/b/c，明确“连续，无剪切”。
- 不足九个有效画面时，允许保留标注“未使用”的空白格；不能添加原剧本没有的台词、行动、物件、人物或反应来填满。
- 超出九格则分页，页边界优先落在自然动作或信息边界。分页不会自动增加生成单元或切镜。
- 单格沿用项目已确认画幅，16:9、21:9或竖屏均可；九格本身不是九个15秒。时长来自镜头表；同镜多关键帧只计算一次镜头时长。
- 不把长场概括到九格并宣称完整覆盖。用户明确只要重点概览时，标记为“节选预览”，列出未绘制镜号。

## 二、一个来源，三种表达

剧本事实 → 已批准 SHOT_BEATS / SHOT_SCORE 与时间线 → 九宫格格表、中文导演稿、英文 H3 稿。不得分别创作三个版本。

每格至少交代：来源镜号与时间、画面注意力目标、景别/机位、主体位置和动作瞬间、视线/动线、道具状态、空间地标、主光方向与明暗大块。只有图上可以看见的东西进入绘图提示词；原台词留在文字镜头表，不依靠图像排版完整对白。

引用用途分清：人物/道具/场景图控制内容连续性；用户提供的素描例图只控制绘制媒介和排版，不继承例图的马车、包裹、桥、时代或剧情。已绑定给 H3 的写实风格图不控制素描完成度。

## 三、绘制规格

### 单格画幅是硬性验收项

继承已确认的影片画幅，不因“九宫格”改为正方形。16:9影片必须让每格**有效画面内框**为16:9；三列三行的整页应为接近16:9的横向画布，考虑边框和间距后计算实际尺寸。示例：每格640×360，间距12像素、四边各12像素，则整页1968×1128；有效格内仍为16:9。其他影片画幅同理。

实际提交给绘图工具的提示词必须明确单格宽高比、整页横向/竖向形状、三列三行、等大有效画面和边距；不能只在事后HTML里补写画幅。保存实际调用提示词，修订稿另标版本，不冒称原图的生成记录。16:9可用约束句：“三列三行横向分镜页，每个框内画面均为宽16高9的横幅，不是正方形；横向展开场景空间，保留左右构图。”工具支持尺寸参数时也设置相应尺寸。

验收须读取真实图片宽高并逐格查看有效内框。记录 `visual_qa.image_size_px`（宽、高）与 `visual_qa.panel_bounds_px`（按格序九项x、y、宽、高；不含框线和页间空白），计算各格宽高比对目标比的相对误差，原则上不超过2%。坐标须依据实际图片核验，不能从目标画幅反推并伪装为实测。整页比例正确并不证明单格正确。

未测量、近方格、拉伸变形或构图被裁切时，不得标为approved。禁止CSS强制拉宽、裁掉上下内容、加空白条来冒充横向构图；应按原镜头计划重新绘制或编辑扩展横向画面。展示用 `width:100%; height:auto` 保持原比例。画幅修订不授权改台词、镜头事件或批量制作下一单元。

白纸底、黑灰铅笔或墨线结构、克制的大块灰阶明暗；线条表达姿态和透视，块面表达光向和空间层次。人物保持可辨认的身形、发型轮廓、服装块面；关键手势、握持、接触点和特写表情应清楚。不要渲染毛孔、发丝、材质微纹、摄影散景或成片调色。

九格等大，白色间距、细黑边框。红色只用于必要动线：人物移动用框内实线，摄影运动放框边并标“推/跟/摇”等短词，视线必要时用虚线；静止画面不加装饰箭头。一格只有一个主要动作瞬间；不能把多个不同时间的人物画成复制人。

画面中最多放短格号和必要箭头标签。可靠的镜号、时间、对应关系用 HTML 文字和格表呈现；若模型画错编号应修正或不让模型绘字，不能让错误图内数字与文字表并存。

绘图提示词与视频提示词分别复制。提示词顺序为：制作型素描九宫格 → 画幅/阅读顺序 → 参考用途 → 每格已决定画面 → 连续性与媒介约束。用中文写，每格给确定选择，不留“中景或近景”等未决描述。

## 四、生成和验收

调用当前可用图像生成工具，并遵循适用的图像技能。已有图片编辑使用图像编辑工具，不用绘制框线或拼贴替代实际素描。排版工具可以为真实分镜图添加格号、字幕表和边框，不能伪造已生成内容。

先检查实际图，再标“已验收”：

1. 网格：三行三列；核对真实像素尺寸及九格有效画面内框比例，并记录上述测量证据；顺序、空格和页范围正确。仅写 `aspect_ratio:16:9` 不算通过。
2. 剧情：每格能对应原镜头，不提前揭示、不跳过关键接触/交接、不添加人物或事件。
3. 连续性：角色轮廓、服装、道具归属、左右关系、光向与场景地标一致；反打允许屏幕坐标改变，但空间关系必须成立。
4. 叙事可读性：缩略状态可读动作和情绪转折；同镜多格确实呈现时间变化，而非无意义重复。
5. 媒介：明显是纸上拍摄分镜，有结构线与明暗块，不是九张写实剧照或精修漫画。
6. 标记：箭头含义清楚，图内编号与格表一致，时间来自唯一镜头账而非逐格累加。

局部内容错误优先只修受影响格；全页媒介错误则使用原格表从新画布重画，不反复继承错误风格。重试不得超出已授权成本和范围；不能无限重试。失败或缺工具时可以交待修稿/格表，但明确状态，不称已通过。

素描验收不代表人脸一致性、真实表演、口型、音色或动态剪接已通过；这些需看后续视频。

## 五、HTML 接入与更新

按 [STORYBOARD_PREVIEW.md](../templates/STORYBOARD_PREVIEW.md) 在本场文字分镜表前放图；全图默认可见、可放大，下面是简洁格表与可复制绘图提示词。每格可定位对应的真实镜头行。图片以 data URI 内嵌，保证 HTML 离线可读；正文全中文，内部 ID 保持稳定。

### Manifest 不能替代 HTML 九宫格

每一条 manifest `pages[]` 都必须对应 HTML 里一个同 `page_id` 的 `<section class="sb-preview">`。只有 JSON、镜头表、文字卡片、单元摘要，或一个裸 `<div class="sb-preview">` 都不算已交付九宫格。待绘制时也要呈现可见的三列三行宽幅占位格：每格包含镜号／绝对时间、已决定画面、连续性约束；未用格明确写“未使用”。这是让用户在没有素描图时仍能审核画面因果，而不是假装已有图片。

长场分页时，manifest 的每一页都必须在 HTML 呈现为一页九宫格，不能只保留第一张或用“六个镜头卡片”概括后续页。交付前运行 `python scripts/storyboard_html_preview_lint.py <html-file> <manifest-file>`；缺页、非 section 容器、九格数量不等于九、格号/镜号/时间不一致、遗漏绘图提示词或复制按钮，都视为未交付。

展示版带格号/箭头，仅供审稿，默认不占 H3 引用槽位。确需将某格用于 H3 时，单独准备无格框、无箭头、无编号的生产关键帧并明确用途；若成片是写实，应另建写实关键帧，不能直接绑定素描为全局风格。

镜头改动时同步格表、绘图提示词和中英视频稿，并把受影响旧图标为“已过期”。只改图不能暗改已批准镜头。已批准首单元文字保持不变，除非用户此次明确授权修改。

## 六、可校核的格表清单

保存 `Storyboard_<scope>.json`，UTF-8。下面为结构说明，不是可交付的占位内容。

- `schema_version`: 1
- `scope_id`: 本次场景范围
- `revision`: 与本轮镜头计划一致的版本字符串
- `shots`: 从同一个最终镜头计划导出的镜头记录，按播放顺序排列；不从九宫格反造镜头表。
  - `shot_id`：全范围唯一，如 S01-H3-001-SH01
  - `scene_id`、`unit_id`
  - `start`、`end`：本次范围的绝对秒数，首镜从0开始
  - `source_beats`：拥有的来源节拍ID，非空列表
  - `dialogue`：原文台词/旁白，含标点；无台词为字符串空值
- `pages`: 顺序页列表
  - `page_id`、`scene_id`、`revision`、`aspect_ratio`（单格，如16:9）
  - `status`: pending / generated / approved / failed / stale
  - `image_path`: 真实本地图片路径；待生成可以为空
  - `visual_qa`: {`passed`: true或false, `notes`: 实际看图结论}
  - `panels`: 恰好9项，`cell` 为1到9；未用项为 {`cell`: 数字, `unused`: true}
  - 有效项包含 `shot_id`、`at`（代表瞬间绝对秒数）、`frame_label`（如SH01a）、`visual`（确定画面描述）、`continuity`（本格关键连续性约束）。

执行 `python scripts/storyboard_manifest_lint.py <清单.json>`。它检查格数、镜号关联、时间顺序/覆盖、同镜多格不重复计时、文件存在和验收状态；不自动检测图内格框或验证实际画幅，不能替代上述像素测量及视觉审查。实际画面与原剧本一致性仍需人工/视觉审查。pending 或 failed 不是“已完成”，即便结构验证通过。

本规范与 clipshot 的适配差异：继承已有范围和画幅，不重复提问；允许尾页未用格，不补剧情；沿用主技能批准门，不额外阻塞；不照搬无限重绘；所有真实视频平台规则仍由原分支负责。
