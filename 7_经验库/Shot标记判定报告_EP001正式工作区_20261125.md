## 1. 问题缘起：为什么要把 34 处拿出单独判

经验库 18.1 记录过一次真实事故：办公室场景 15 镜的提示词与装配 JSON 中，**90 处 `[Shot N]` 全写成 `[Shot 1]`**，等于告诉 H3「15 段都是第 1 镜开头」，镜次信息完全丢失。用户据此要求“经验库里还有没有别的模板引用过这个 bug”，进而要求把**正式工作区**的 34 处也按同款流程查一遍。

判定核心问题只有一个：

> 这 34 处 `[Shot 1]`，是 18.1 那种“多镜装进同一视频却全标首镜”的 bug，还是别的合法用法？

## 2. 事实清点：34 处在哪里、长什么样

| 项 | 事实 |
|---|---|
| 文件 | `5_漫剧/EP001-同学会暗恋/剧集/EP001/视频提示词.md` |
| 块数 | 5 块 MOTION：`MOTION-EP001-001` ～ `MOTION-EP001-005` |
| 每块 `[Shot 1]` 处数 | 6 / 7 / 8 / 7 / 6，合计 **34** |
| 首帧声明 | 每块各自写 `<Picture 1> aligns with the 0.00-second mark as the opening frame of [Shot 1]` |
| 帧素材 | 每块各自独立 `SHOT-EP001-00N.png` 起始帧 + 独立时长 |
| 出片方式 | README 明示 `videos/MOTION-EP001-*.mp4` 为**逐镜片段（未拼接）**，手册 N12 按段验收 |
| 交付口径 | 正片取 `seg_*.mp4`；各 MOTION 块是独立片段，不是一条 15 镜 timeline |

这一点是分水岭：18.1 的前提是**多镜装进同一条视频**，EP001 的前提是**每块单独出一条视频**。

## 3. 四条判定依据

### 依据 1：官方语义就是 `[Shot 1]` = opening shot

`99_参考/SKILLS/tudou-shotlist-builder/reference/MINIMAX_H3_BASE_EN.md`：

- L16：`at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.`
- L22：`Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video`
- L51：`<Picture 1> is the actual first frame of the video at 0.00 seconds and belongs to [Shot 1]`

所以在**单镜独立视频**里，首帧写 `[Shot 1]` 是规范本身的要求，不是错。

### 依据 2：5 块是“逐镜独立出片”，不是“15 镜合一 timeline”

每块都有自己的 0.00 秒、自己的起始帧、自己的时长、自己的输出 mp4。完整链条是：

```
SHOT-EP001-001.png + MOTION-001 → MOTION-EP001-001.mp4
SHOT-EP001-002.png + MOTION-002 → MOTION-EP001-002.mp4
...（5 段各自独立）
```

这与 18.1 的“15 镜共 90 处全写 `[Shot 1]`、镜次信息全丢”结构不同。18.1 的 bug 前提是**一条视频里要区分多个镜次**，EP001 不成立。

### 依据 3：门禁没有报镜号问题

`1_AI漫剧全流程解决方案/AI漫剧全流程自动化方案/h3_lint/check_prompt_content.py` 跑法：

```bash
python check_prompt_content.py <shotlist.csv> --prompt-md "5_漫剧/EP001-同学会暗恋/剧集/EP001/视频提示词.md"
```

结果：**没有任何 `[Shot 1]` 报警**。脚本的镜号断言只作用于 CSV 六列（`PROMPT_SECTIONS`：`subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`），不会把 md 里的 `[Shot 1]` 当镜号错。唯一提示是 `## MOTION-` 与脚本期望的 `## SHOT-` 标题格式不符——属格式偏好，非镜号问题。

### 依据 4：强改会引入真 bug

如果把 5 块改成 `[Shot 2]` ～ `[Shot 5]`，等于对每一条独立视频说“首帧属于第 N 镜”，而它实际是该视频的 opening frame。这**违背官方定义**，把合法文件改成真正坏的提示词。
