# H3 Ref2VA 多参考分工固化与现状核对

> 调研日期：2026-11-27
> 问题：MiniMax H3 Ref2VA 支持 **9 图 / 3 视频 / 3 音频**，并建议给每个参考显式分配「身份 / 风格 / 运动 / 音色」任务——**本生产线做的 R2V 案例到底用没用？**
> 结论一句话：**用了 R2V，但只用了一个子集**。现役案例是「4 图 + 1~2 音频 + 0 视频」的**本地 Director 档**，9/3/3 的能力没有用满；视频参考槽（运动参考）在所有正式案例里都是空的。

---

## 一、官方契约（2026-11 核对）

### 1.1 输入上限（ComfyUI 官方文档）

| 类型 | 基础 H3 / R2V 节点 | H3 Max Reference 节点 | 附加约束 |
|---|---|---|---|
| 参考图 | **最多 9 张** | 合计最多 **12 个文件** | — |
| 参考视频 | **最多 3 段** | 同上 | 每段 **2–15 秒**；帧率 **23.976–60 FPS**；三段总时长 **≤15 秒** |
| 参考音频 | **最多 3 段** | 同上 | 每段 2–15 秒；三段总时长 ≤15 秒；**必须有至少一张参考图或视频作视觉锚点**（不能只给音频） |
| `ref_image_size` | `match`（缩到生成分辨率，快）/ `max`（最长边 2048，保真高但慢） | 另有 `reference_detail` 在分辨率与成本间权衡 | — |

提示词要求：
- 用**顺序标签**引用：`Image 1` / `Video 1` / `Audio 1`（不是文件名）。
- **显式分配任务**：官方原话 "Assign each reference a job (identity, style, motion, voice) and describe the target shot; **explicit assignments tend to work much better**"。
- 全参考模式的标准 rewrite 输出是**六段固定顺序**：`subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`（本项目门禁正是照此检查）。
- `summary` 开头要挂**任务类型标记**，官方定义六种：`keyframe completion` / `reference generation` / `video editing` / `video continuation` / `audio reuse` / `audio reference`，用 `+` 连接、同类不重复。改片还须以 `The target video is an edited version of <Video 1>.` 开头。
- 一个素材可承担多个任务，但要**逐个列清**；「Use Video 1 for everything」是官方点名的反例。
- `retention_analysis` 要写可检查的可见属性保留程度，不是笼统「保持一致」。

### 1.2 四类任务的推荐绑定（窄绑定原则）

| 任务 | 由什么承载 | 提示词写法要点 |
|---|---|---|
| **身份 identity** | 参考图（角色定妆板 / 三视图 / 脸部多格） | 点名脸型、发际线、服装层次等可逐帧检查的锚点 |
| **风格 style** | 参考图（场景板 / 色板 / 光线氛围板） | 写清只作用于哪部分，如「风格化只作用于环境，包装保持写实」 |
| **运动 motion** | **参考视频**（肢体动作、镜头路径、动作时序、物理交互、剪辑节奏） | 必须窄绑定：`Reference video 1 controls movement and timing only; ignore its performer, wardrobe, location, colour grade and audio.` |
| **音色 voice** | 参考音频（声线 / 语速 / 节拍 / 环境音） | `voice timbre only, without copying the source words or waveform`；必须有视觉锚点 |

**冲突处理**：写明优先级（如 `Priority order: 1. Image 1 controls identity... 2. Video 1 controls motion... 3. text controls framing`），并主动消解矛盾（身份图披发而动作视频戴帽，就明确最终保留哪个）。**只选一个镜头权威**：要么从视频迁移镜头，要么用文本指挥镜头。

### 2.3 现役「4 图 + 音频」槽位契约（已固化在装配器里）

`csv_to_timeline.py` 的 `REF_SLOTS` 与 `VOICE_COLUMNS`：

```
<Picture 1> = 每镜关键帧 / vibe 漫画格（每镜换）      → refs[0]（0 基，可用 --ref-base 1 切换）
<Picture 2> = 角色定妆板（全片固定）                  → refs[1]  ← 身份
<Picture 3> = 场景板（同场景固定）                    → refs[2]  ← 风格 / 场景
<Picture 4> = 服装 / 双人站位板（全片固定）           → refs[3]
<Audio 1..3> = 角色参考音色（ref_voice / _2 / _3）    → refAudios（恒 0 基）← 音色
refVideos: []   ← 装配器写死为空，19 字段 CSV 没有视频参考列
```

**注意基数差异**：本项目导演台实跑验证为 **0 基**（`<Picture 1>` = index 0），旧版/部分导演台为 1 基；`refAudios` **恒 0 基**不随 `--ref-base` 改。这一段是经验库实跑回灌，换导演台版本必须单镜实测确认无错位。

### 2.4 提示词里的分工写得怎么样

三个案例（EP001、WUXIAFLOW、东方不败）的 `视频提示词.md` 都用了完整六段式，并在 `subject_definitions` / `retention_analysis` 里显式定义每个槽位：

```
> subject_definitions: <Picture 1> aligns with the 0.00-second mark as the opening frame...
   <Picture 2> is SHENYU ("SHENYU"), the 27-year-old East Asian man: 183cm lean build...
   <Picture 3> is the corridor plate: long hall receding along the horizontal axis...
   <Picture 4> is the two-character costume pair board. Style lock: pure stylised 2D comic illustration...
> retention_analysis: <Picture 1> fully_preserved - opening framing...; <Picture 2> fully_preserved -
   face, hair and outfit; <Picture 3> partially_preserved - corridor geometry locked;
   <Audio 1> reference - voice timbre drives her line only.
```

EP001 还做了**音频数量升级**：S003 挂双声线（`<Audio 1>` LINWAN / `<Audio 2>` SHENYU），S004 道具板替换第 4 槽（钥匙扣尺度锚，防 4step 放大）。

**判定**：
- ✅ **身份**：`<Picture 2>` 三视图长期固定，写得最扎实（门禁还强制描述 >80 字符）。
- ✅ **风格**：`<Picture 3>` 场景板 + `Style lock:` 画风词，有 partially/fully 保留强度区分。
- ✅ **音色**：`<Audio 1..2>` 明确写 `voice timbre ... without copying source words`，合规。
- ❌ **运动**：**没有任何参考视频**；动作 / 运镜全靠 `detailed_description` 文本描述（缓推、固定机位、0.00 秒锚定）。这是**最大缺口**，也是官方 9/3/3 里唯一完全没碰的一类。
- ⚠️ **9 图上限只用了 4**：剩余 5 个图槽可留给道具板、表情板、多角度身份格，目前靠「第 4 槽轮换」挤占。

## 三、为什么会出现这个缺口（不是纯疏忽）

| 原因 | 说明 |
|---|---|
| **生成档设计如此** | 本生产线主力是 `generate` 档，`generate` 的参考音色**只锁 F0、不锁语速与情绪**，韵律靠 prompt；逐句情绪要走 `source/TTS` + `fully_copy`。运动同理，走文本运镜词而非视频参考，是「文本权威」路线。 |
| **逐镜独立出片** | 每镜单独提交、尾帧锚定续接；给每段再挂一段 2–15s 运动参考视频，会与「文本指挥镜头」抢控制权，且参考视频总时长上限 15 秒，长段必然拆。 |
| **装配器能力边界** | `csv_to_timeline.py` 的 `build_segment()` 写死 `"refVideos": []`；19 字段 CSV 无对应列。要用运动参考，必须扩字段 + 改装配器 + 改门禁，不是填个值就行。 |
| **素材供给现实** | `voices/*.wav` 与干净参考视频都尚未落到仓库（属「人工准备」），运动参考视频更缺。 |

## 四、「身份 / 风格 / 运动 / 音色」四分工固化规范

### 4.1 槽位总表（本项目标准）

| 槽位 | 职责 | 承载 | 保留强度写法 | 生产纪律 |
|---|---|---|---|---|
| `<Picture 1>` | 起始帧 / 构图锚 | 每镜 vibe 格 | `fully_preserved` + 0.00 秒对齐 | 每镜一张，不复用 |
| `<Picture 2>` | **身份 identity** | 角色三视图 / 定妆板 | `fully_preserved`（脸型、发际线、服装层次） | 全片固定；门禁强制 >80 字符 |
| `<Picture 3>` | **风格 style / 场景** | 场景板 + `Style lock:` | `partially_preserved`（布局、光向锁；灯态可随镜变） | 同场景固定 |
| `<Picture 4>` | 服装 / 道具 / 双人站位 | 配对板或关键道具板 | `fully_preserved`（物件细节） | 换道具即换镜，需说明 |
| `<Video 1..3>` | **运动 motion** | 2–15s 干净动作 / 镜头路径参考 | `reference - motion and timing only` + 显式 ignore 清单 | 现役未启用；见 4.3 |
| `<Audio 1..3>` | **音色 voice** | 角色干声 5–10s | `reference - voice timbre only, without copying source words` | 恒 0 基；需视觉锚点 |

### 4.2 提示词固化模板（六段式 + 窄绑定）

```
subject_definitions:
  <Picture 1> is the opening frame of [Shot N], aligned with the 0.00-second mark: <构图与站位>.
  <Picture 2> is <角色名>, the <年龄> <性别>: <脸型/发型/服装层次等可检查锚点>.
  <Picture 3> is <场景> plate: <布局/光向/关键物件位置>.
  <Picture 4> is <服装配对板或道具板>: <需锁定的细节>.
  <Audio 1> is the voice-timbre reference for <Subject 1> (S1).
summary:
  [reference generation + audio reference] Create a <时长>s <风格> shot in which <主体> <动作>.
  <Picture 2> supplies identity, <Picture 3> supplies environment and style,
  <Audio 1> supplies voice timbre only.
retention_analysis:
  <Picture 1>: fully_preserved - <构图/站位/光向>; <Picture 2>: fully_preserved - <身份锚点>;
  <Picture 3>: partially_preserved - <锁什么/允许什么变>; <Picture 4>: fully_preserved - <细节>;
  <Audio 1>: reference - vocal timbre guides <Subject 1> without copying the source words.
detailed_description:
  [Shot N] <主体 + 动作 + 运镜（文本权威）> <Subject 1> (S1) says ... using voice reference <Audio 1> ...
overall_soundscape: <环境音>
non_diegetic_music: N/A
```

写 `summary` 时：**每个素材的 job 单列一句**，禁止 `Use Video 1 for everything` 这类笼统写法。

### 4.3 何时启用运动参考（`<Video 1>`）

| 场景 | 是否挂运动参考 | 做法 |
|---|---|---|
| 常规对白 / 微动作镜（本生产线多数） | **不挂** | 文本运镜词即权威；保持 4 图 + 音频，最稳 |
| 复杂肢体动作 / 武打 / 特定镜头路径（如东方不败崖顶过招） | **可试挂 1 段** | 参考视频 2–15s、23.976–60fps；提示词写 `Reference video 1 controls movement and timing only; ignore its performer, wardrobe, location, colour grade and audio.` 并给出 Priority order |
| 多镜头衔接 / 续写 | 不挂（改走尾帧锚定） | `video continuation` 任务类型 + 上段末帧作下段首帧，与现行拆段纪律一致 |
| 改片 / 换人 | 挂（改走 V2V / RV2V） | `video editing` 任务类型，摘要以 `The target video is an edited version of <Video 1>.` 开头 |

**启用前的工程前提**（缺一不可）：
1. CSV 增加 `ref_motion_1..3` 列（19 → 最多 22 字段），并在 `REF_SLOTS` / `VOICE_COLUMNS` 旁新增 `MOTION_COLUMNS`；
2. `csv_to_timeline.py:build_segment()` 把 `"refVideos": []` 改为按列生成 `video_obj()`；
3. 新增门禁 `check_ref_contract.py`：校验视频段数 ≤3、时长 2–15s、总时长 ≤15s、音频必须有视觉锚点、任务类型标记合法；
4. `check_prompt_content.py` 增检：`<Video N>` 必须有 `reference - motion ... only` 的窄绑定句 + ignore 清单；
5. 先用**单镜 A/B**（同提示词、同 seed，挂 / 不挂运动参考）实测，确认不抢身份与构图权威，再进批量。

> 本次只固化规范，**未改装配器与 CSV 契约**——改动会影响 19 字段全链，须单独评估后排期。

## 五、直接回答提问

> 「目前做的案例 h3 r2v 没有使用吗」

**用了 R2V，但没用满，也没有用「运动参考」。** 具体：

1. **用了**：EP001、WUXIAFLOW、东方不败三个案例的工作流模式都是 `r2v — 参考主体生视频`，提示词是完整六段式，槽位分工（身份/风格/音色）写得比官方示例还细。
2. **没用满**：每镜固定 4 图 + 1~2 音频，只用了官方 9 图上限的 4/9、3 音频的 1~2/3。
3. **完全没碰**：**3 个视频参考槽 = 0**，即官方四分工里的「运动 motion」一类在所有正式案例里都没用。唯一出现 `refVideos` 的是导演台 `external_groups_r2v.json`（外部测试组），不属于本生产线案例。
4. **原因**：不是单纯遗漏——本生产线走「逐镜独立出片 + 文本运镜权威」路线，装配器也没给视频参考留字段。是否启用运动参考，应按 4.3 的判断表按镜头评估，而非全量补齐。
